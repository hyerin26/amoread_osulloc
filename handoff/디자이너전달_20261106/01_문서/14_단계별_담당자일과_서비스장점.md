## 3. 단계 사이를 지나가는 것
| 만든 단계 | 데이터 | 쓰는 단계 |
|---|---|---|
| 01 | 목적, 명분, 콘셉트, 타깃, 기간 | 02 구성안 추천, 04 문구 초안, 05 문서 표지, 캘린더 |
| 02 | 구좌(이름, 순서, 목표), 구좌별 레이아웃 출처·참고 레퍼런스 | 04 와이어프레임, 05 문서 |
| 03 | 할인 행(상품, 할인율, 기간, 상시·하루특가) | 02 Zone 구좌 초안, 04 상품 카드 가격, 05 엑셀 |
| 04 | 문구, 구좌별 상품, 가격 노출, 요청사항 | 03 '배치된 구좌' 표시, 05 문서 |

같은 구좌는 하나의 데이터예요(`page.sections`). 02와 04는 같은 구좌를 서로 다른 목적으로 보는 화면이에요.

## 4. 02와 04를 합칠지
| | 02 구성 | 04 구좌 편집 |
|---|---|---|
| 목적 | **무엇을, 어떤 순서로, 어떤 사례를 참고해서** (구조를 정함) | **어떻게 보이게** (내용을 채움) |
| 보는 범위 | 페이지 전체 흐름과 여러 레퍼런스를 넓게 비교 | 구좌 하나를 자세히 |
| 주로 하는 일 | 추천 비교, 레퍼런스 고르기, 구좌 넣고 빼기 | 문구 고치기, 상품 고르기, 요청사항 |
| 화면 모양 | 왼쪽 구좌 순서 + 오른쪽 구좌별 추천 레퍼런스 큰 카드 | 구좌 목록 + 모바일 와이어프레임 + 편집 패널 |

판단: **나누는 것이 맞아요.** 합치면 레퍼런스를 넓게 비교하는 일(02)이 편집 패널 안 드로어로 좁아지고, 브리프에서 바로 구성을 잡는 단계가 사라져요. 겹치는 동작(구좌 추가·순서·레퍼런스 바꾸기)은 두 화면 모두에서 할 수 있게 두고, 같은 데이터를 쓰므로 한쪽에서 바꾸면 다른 쪽에도 그대로 보여요.

이 흐름에서 바뀌는 점(지금 대비):
- 단계 순서: ② 상품·할인과 ③ 페이지 구성의 순서를 바꿔 **02 구성 → 03 상품·혜택**. 할인부터 하는 경우는 03에서 시작하면 되고, 02가 03의 Zone을 써요
- ③ 페이지 구성은 없애지 않고 **02 구성으로 발전**(레퍼런스 추천, 구성안 제안 추가)
- 디자이너 'AI 기획'의 대표 카피는 01 브리프 또는 02 구성 맨 위 '기획 방향'에 둠

## 5. 서비스가 주는 장점 (모두 가설, 인터뷰 C3·E2·G2로 확인)
| 장점 | 근거 |
|---|---|
| 명분부터 디자이너 전달까지 **기획안 하나**에 모임. 같은 내용을 여러 파일에 다시 적지 않음 | 지금 업무는 캘린더·엑셀(PROMO_WORK)·문서가 따로라고 추정 |
| 판단 근거가 **판단하는 자리 옆**에 있음 (명분 D-day, 지난 행사 성과, 원가율, 반응) | 멘토님 툴 데이터 |
| 지난 페이지와 사례를 **구좌 단위로 다시 씀** (레퍼런스) | 매번 처음부터 구성하지 않음 |
| 할인과 페이지가 **같은 상품·가격**을 봄. 페이지에 없는 할인 상품, 할인 안 정해진 페이지 상품을 바로 알려줌 | 다음에 할 일, 배치된 구좌 표시 |
| 디자이너 문서가 **자동으로** 만들어지고 원가는 빠짐 | 05 |
| PROMO_WORK에 붙일 엑셀이 **형식 그대로** 나옴 | 멘토님 툴 내보내기 |

## 6. 결정·확인할 것
1. 이 5단계(01 브리프 → 02 구성 → 03 상품·혜택 → 04 구좌 편집 → 05 미리보기·내보내기 + 레퍼런스)로 갈지
2. 02의 '구성안 제안'과 04의 '문구 초안'을 무엇으로 만들지: 규칙(목적별 템플릿, 명분 씨앗) 먼저, AI는 승인 뒤
3. 레퍼런스 데이터 출처 (디자이너 예시 / 직접 등록 / 지난 기획안 구성)
4. 대표 카피를 01에 둘지 02에 둘지
