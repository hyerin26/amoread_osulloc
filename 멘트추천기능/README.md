# 멘트 추천 기능

기존 AMOREAD 로컬 FastAPI 앱과 Claude Agent SDK 호출 방식을 재사용합니다. 별도 서버·포트·프런트엔드 API 키가 필요하지 않습니다. 기존 기획안 데이터는 마이그레이션하지 않습니다.

## 사용

1. 기존 앱을 실행하는 Python 환경에서 `planner/requirements.txt`를 설치합니다. Python 3.11 이상을 사용하세요. 점검 당시 `workspace/.venv`는 Python 3.9였으며 이 환경은 변경하지 않았습니다.
2. 기존 앱에서 사용하는 조직 승인 Claude Agent SDK 인증과 모델 설정을 준비합니다. 모델은 `planner.config.CLAUDE_MODEL` / `PLANNER_CLAUDE_MODEL` 값을 그대로 사용합니다. 브라우저에 키를 넣지 마세요.
3. `workspace/amoread_app`에서 기존 명령 `python -m planner.server`로 실행하거나 기존 실행 스크립트를 사용합니다. 이미 실행 중이면 재시작 후 편집 화면을 새로고침합니다.
4. 홈에서 저장된 기획안을 열고 **구좌 편집 → 문구 → AI 카피 추천**을 누릅니다. 현재 v2 화면에서는 구좌 편집이 03 단계로 표시됩니다.
5. 메인·서브 세트 / 메인만 / 서브만, 톤을 선택하고 3개 후보 중 하나를 적용합니다. 적용 전에는 현재 문구를 바꾸지 않습니다. 적용 후 직접 수정하거나 실행 취소할 수 있습니다.

SDK 상태 API는 패키지 설치 여부만 확인하며 인증이나 모델 접근 성공을 보장하지 않습니다. 실제 Claude 호출은 인증과 모델 권한이 있어야 성공합니다. 실패 시 예시 추천으로 대체하지 않습니다.

## 구조

- `domain.py`: 문맥 화이트리스트, 프롬프트, JSON 스키마, 결과 검증
- `provider.py`: 기존과 같은 `ClaudeAgentOptions` / `query` / `structured_output`
- `api.py`: 기존 앱에 `/api/am/copy/*` 추가, 비동기 작업·취소·종료 처리
- `static/core.js`: 문맥 스냅샷·변경 감지·부분 적용 검증
- `static/editor-plugin.js`, `static/editor.css`: 추천 UI
- `tests/`: 서버·검증·기존 앱 통합·프런트엔드 로직 테스트

이 폴더는 저장소 루트에 두어야 합니다. 기존 파일의 통합 변경은 `planner/server.py`, `planner/static/v2/editor.html`, `planner/static/v2/editor.js` 3개입니다. 기존 앱의 Host·토큰 검사와 CSP를 그대로 적용합니다.

## 동작과 범위

- 브리프, 키워드, 선택 구좌와 이웃 제목, 선택 상품의 이름·카테고리, 검증 가능한 일정·단순 할인 문맥을 구성합니다.
- 상품 원가·매출·후기는 전달하지 않습니다. 자유 입력 브리프에서 원가·마진·매출 등 내부 정보 키워드가 포함된 줄을 제외하지만, 임의로 기입한 모든 민감 정보를 자동 식별하는 기능은 아닙니다.
- 복합 혜택은 최종 할인가를 추정하지 않고 숫자 혜택 문맥을 생략합니다. 미반영 할인은 먼저 반영하거나 되돌려야 합니다.
- 메인 60자·서브 200자(브라우저 UTF-16 기준), 중복, 근거 ID, 수치, 일부 과장·효능 표현을 검사합니다. 검증 실패 시 한 번만 재생성합니다. 모든 의미·상품 사실·표시광고 적합성을 보장하지 않으므로 게시 전 담당자가 검토해야 합니다.
- Claude 파일·셸·MCP 도구를 비활성화합니다. 사용자 설정 파일도 불러오지 않습니다.
- 추천 이후 문구·상품·브리프 변경 시 이전 결과 적용을 막습니다. 다른 구좌로 이동해도 결과는 원래 구좌에 보관합니다. 첫 메인 비주얼 제목 적용 시 브리프 대표 카피도 동기화하며 실행 취소로 함께 복구합니다.
- 적용 정보는 해당 구좌 `v2.copyRecommendation`에 모델·프롬프트 버전·요청 ID·후보 ID·근거 ID·시각으로 저장합니다. 추천 목록은 메모리에만 있으며 새로고침하면 사라집니다.
- 동시 작업 1개, 분당 6개 요청, 전체 120초 제한. 완료 작업 최대 40개, 보관 1시간 후 다음 요청 시 정리합니다. 서버 재시작 시 진행 중·메모리 결과는 사라집니다.

## 검증

저장소 루트에서 Python 3.11 이상 환경으로:

```sh
python -m pytest 멘트추천기능/tests -q -p no:cacheprovider
node 멘트추천기능/tests/core.test.cjs
```

2026-11-12 결과: Python 18개 테스트 통과, JavaScript 12개 assertion 통과. 별도 임시 테스트 환경(Python 3.14)에서 SDK import와 기존 앱 전체 로딩을 확인했습니다. 브라우저에서는 합성 프로젝트와 명시적으로 주입한 모의 제공자로 추천 3개 표시, 원문 유지, 수동 수정 후 적용 차단, 메인 단독 적용·서브 유지, 실행 취소, 새로고침 후 저장 내용, 브리프 동기화와 다른 구좌 유지까지 확인했습니다.

**실제 Claude 호출·인증·생성 품질은 이번 검증에 포함하지 않았습니다.** 운영 코드에는 모의 제공자가 없고, 모의 제공자는 테스트 코드에만 있습니다. 사용자 원본 데이터는 테스트에 사용하지 않았습니다.

## 01 브리프 메인 카피

브리프의 기존 **AI 제안** 버튼도 동일한 로컬 서버·Claude 제공자를 사용합니다. 구좌가 없는 기획안에서도 명분·키워드·컨셉·대상 고객 등 저장된 브리프로 메인 카피 3개를 제안합니다. 후보를 선택하기 전에는 기존 메인 카피를 유지하며, 적용하면 `brief.key_copy`에 기존 저장 흐름으로 저장합니다. 브리프 입력이 바뀌면 기존 후보 적용을 차단합니다. 기존 카피 틀 제안은 그대로 유지합니다.

추가 통합 파일: `planner/static/v2/brief.html`, `planner/static/v2/brief.js`. UI 연결 모듈은 이 폴더의 `static/brief-plugin.js`입니다. 브리프 추천 API는 `scope=brief`, `target=headline`을 사용하며 서버에서 임의 상품 문맥을 제외합니다. 브리프는 선택한 카피를 기존 `brief.key_copy` 필드에 저장합니다.

추가 검증: Python 총 19개 통과. 구좌가 없는 브리프 생성과 부분 적용 제한을 검증했습니다. 실제 Claude 인증·호출을 제외하고 합성 데이터·모의 응답으로 브리프 화면 추천 표시·선택 적용·저장을 확인했습니다.

## 설명의 AI로 문구 다듬기

구좌 편집의 설명란 아래 **AI로 문구 다듬기** 버튼을 누르면 입력한 설명을 바탕으로 3개 퇴고안을 만듭니다. 추천 영역의 `설명 다듬기` 모드에서도 사용할 수 있습니다. 어순·호응·리듬·중복을 정리해 자연스럽고 절제된 광고 설명으로 다듬도록 지시하며, 뜻·상품 대상·사용 상황을 유지하고 새 맛·향·산지·혜택·효능을 추가하지 않도록 지시합니다. 실제 의미 보존과 표현 품질은 게시 전 확인해야 합니다.

원문을 함께 표시하고, **이 설명 적용**을 눌러야 설명만 변경합니다. 메인 카피는 그대로 유지하며 기존 저장·실행 취소를 사용합니다. 빈 설명은 요청하지 않고 안내합니다. 기존 숫자라도 사실 근거가 없으면 검증에서 제외될 수 있습니다. 요청은 기존 API의 `task=polish`, `target=subhead`로 구분하며 프롬프트 버전은 `section-copy-v2`입니다.

검증: Python 총 24개 테스트와 JavaScript 12개 assertion 통과. 퇴고 모드·원문 전달·메인 잠금·빈 설명 및 잘못된 범위 거부를 확인했습니다. 화면에서는 합성 데이터·모의 응답으로 버튼 동작과 원문 비교, 설명만 적용·저장을 검증했습니다. 실제 Claude 호출 및 퇴고 품질 평가는 포함하지 않았습니다.

## 브리프와 다음 단계 동기화 수정

02 구좌 구성 상단의 분류·기간·키워드·메인 카피를 저장된 기획안 값으로 표시합니다. 새 구성의 첫 hero 구좌에 브리프 카피를 넣으며, 브리프 카피 수정·삭제 시 기존 첫 hero 구좌도 함께 저장합니다. 예전 기획안에 오래된 hero 제목이 있으면 브리프의 비어 있지 않은 카피를 기준으로 다시 맞춥니다. 다른 구좌와 상품·설명은 보존합니다.

검증: 기존 Python 24개 통과 및 `node 멘트추천기능/tests/brief-flow.test.cjs` 회귀 검증. 합성 기획안으로 브리프 카피 입력 직후 상단 단계 링크를 눌러 02 요약과 03 메인 카피에 같은 값이 표시되는 것을 브라우저에서 확인했습니다.
