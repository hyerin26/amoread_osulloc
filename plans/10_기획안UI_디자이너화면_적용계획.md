## 2. 단계별 구현

모든 단계 공통
- 데이터 저장 형식은 바꾸지 않는다 (`api.py` `ProjectReq`, `store.py`). 바꿔야 하면 그 단계 전에 따로 묻는다
- 구조를 바꾸는 화면은 고치기 전후 `id=`, `data-` 목록을 대조한다
- 검증: JS 구문 검사, CSS 중괄호·변수 점검, 사용자 수동 확인 (자동 화면 시험 금지). 순수 함수는 node 단위 시험 (승인 필요)
- 되돌리기: 단계 시작 전 해당 파일을 `workspace/_backup_D<n>_<날짜>/`에 복사

### D0. 공통 부품 (작음)
- 목적: 아래 화면들이 같은 부품을 쓰게 한다
- 파일: `ds.css`, `core.js` `ICONS` (디자인 세션 소유)
- 내용
  - 단계 머리 패턴: 작은 제목 12/18 보조색, 제목, 설명, 오른쪽 주 버튼. 기존 `.masthead`를 확장하고, 단계용은 새 클래스 하나만 둔다
  - 안내 띠: 기존 `.info-box`를 v2.5.1 모양(회색 면, 12px 라운드, 굵은 첫 구절)으로
  - 묶음 탭(세그먼트): 회색 묶음 + 선택 흰 면·녹색 글자. 기존 클래스가 없어 새로 하나
  - 아이콘 추가: grip, undo, redo, more, arrow-right, panel (디자이너 `ICON_PATHS`와 같은 24 그리드 경로)
- 데이터 영향: 없음
- 완료 기준: 기존 화면 모양이 바뀌지 않음 (새 클래스는 아직 아무도 안 씀)

### D1. 기획안 목록 = 디자이너 홈 (작음)
- 파일: `hub.js` `paintList`, `paintListBody`, `am.css`
- 내용: 1장 표의 홈 구조. 검색(제목·명분·기간, 화면에서만 거름). 유지: 이어서 하기 카드, `지난 행사 상품·할인 가져오기`, 기존 작업대 기획안 가져오기, 예전 작업대 임시 내용 옮기기, 상태, 삭제(두 번 눌러 확인)

### D2. 기획안 머리와 단계 막대 (중간)
- 파일: `hub.js` `paintHub`, `paintSteps`, `paintSave`, `am.css`
- 내용: 머리(제목 입력 28/36/700, 기간·명분 한 줄, 상태). 그 아래 단계 막대를 디자이너 앱 막대 모양으로 바꾸고 상단 막대 아래에 고정. 단계 이름 아래 지금 상태 문구(예: "상품 8 · 하루특가 4")는 유지(데이터 요소). 오른쪽: 저장 상태(해요체 "저장했어요"), 실행 취소·다시 실행(D4 이후 활성), `다음: ② 상품·할인 →` 주 버튼
- 유지: ② 저장하지 않은 변경이 있으면 떠나기 확인(`canLeave`), 옆 패널 접기
- 시험: 단계 이동, ② 변경 중 이동 시 확인창, 키보드 Tab·Enter, 900/390px에서 단계 막대 가로 스크롤

### D3. ① 명분·브리프 (작음)
- 파일: `brief.js` `renderBrief`, `am.css`
- 내용: 단계 머리 + 안내 띠 + 2열 카드. 옆 패널 카드(명분 근거, 컨셉 이력, 캘린더 반영)는 디자이너 '제안 근거 확인' 카드 모양으로
- 데이터 영향: 없음 (필드와 자동 저장 그대로)

### D4. ③ 페이지 구성: 구좌 목록과 정렬 (중간)
- 파일: `page.js` `paintOutline`, `onOutline`, 새 `am/history.js`, `am.css`
- 내용
  - 구좌 목록 행을 디자이너 모양으로, 선택은 `--sel-fill`과 1px 선
  - 끌어서 순서 바꾸기: 손잡이 포인터 드래그, 삽입선(`--move`), 목록 경계 자동 스크롤, 목록 밖에 놓으면 취소, Esc 취소. 규칙은 디자이너 `sectionInsertion`, `reorderSectionList`와 같게 (섹션 객체를 통째로 옮겨 `sectionId`, 슬롯, `designNotes`가 함께 감)
  - 키보드: 손잡이에서 Alt+↑/↓, 기존 위·아래 버튼 유지
  - 실행 취소·다시 실행: `page.sections` 대상 70단계. ② 할인 행과 하루특가는 대상 밖 (수동 저장 유지). 단계를 옮기면 기록을 비운다
- 데이터 영향: 섹션 순서만 (`payload()`가 `order`를 다시 매김)
- 시험: 정렬 함수 단위 시험(앞·뒤·인접·같은 자리·없는 ID), 드래그 후 새로고침 유지, 실행 취소로 원래 순서, 하루특가 섹션 이동

### D5. ④ 구좌 편집 신규 (큼)
- 파일: 새 `am/editor.js`, 새 `am/wire.js`(와이어프레임 그리기, ⑤와 함께 씀), `hub.js` `STEPS`의 `soon` 제거와 `paintTab` 연결, `am.css`
- 내용
  - 3열 배치. 980px 이하는 편집 패널이 겹쳐 열림, 700px 이하는 1열 (디자이너 `02_SCREEN_FLOW_SPEC.md` 반응형 표)
  - 와이어프레임: 우리 레이아웃 7종(`LAYOUTS`)마다 모바일 모양. 하루특가 섹션은 날짜를 골라 그날 상품 보기
  - 문구 바로 고치기: 메인 카피(`headline`), 서브 카피(`subhead`), 버튼 문구(`cta`). 한 번 클릭, Enter 저장, Shift+Enter 줄바꿈, Esc 취소, 다른 곳 누르면 저장, 한글 입력 중 Enter 무시(`isComposing`), 편집 패널과 바로 맞춤, 실행 취소 대상
  - 편집 패널 탭: 콘텐츠(레이아웃 바꾸기, 구좌명, 카피, 역할) / 상품·가격(슬롯 상품, 가격 노출 방식 `DISPLAYS`, 가격은 ② 할인율을 읽기만 + `② 상품·할인에서 바꾸기`) / 디자인 요청(`designNotes`). 탭은 패널 안에서 스크롤해도 위에 고정
  - 상품 교체: 기존 `core.js` `attachPicker` 사용, 슬롯의 `seq`만 바꿔 `slotId`·`customCopy` 보존
  - 상품 카드: 할인율·행사가 `--price`, 정가 취소선, 상품 정보 없음·가격 미정 표시는 문구로
- 데이터 영향: 기존 필드만 씀 (`headline`, `subhead`, `cta`, `slots[].seq`, `slots[].customCopy`, `designNotes`, 섹션 가격 노출 방식). 원가는 화면에 넣지 않음
- 시험: 문구 편집 5가지 키 동작, 패널 동기화, 실행 취소, 상품 교체 후 슬롯 ID 유지, 탭 고정(긴 패널 스크롤), 1560/1280/900/390px

### D6. ⑤ 확인·전달 맞추기 (중간, 통합 세션 4차 결과 위에서)
- 파일: `deliver.js`(통합 세션 소유), `am/wire.js`
- 내용: 미리보기의 와이어프레임을 `wire.js`로 바꿔 ④와 같은 모양으로. 문서 종이 모양, 요청사항 바로 수정 칸 모양을 S07에 맞춤
- 순서: 4차의 ⑤가 먼저 나오고, D5 이후 와이어프레임만 교체
- 4차 결과(2026-11-06, plans/11): `deliver.js`의 전달 문서 미리보기(`docBody`, `DOC_CSS`)와 인쇄 흐름(`printPdf`, `#amPrintRoot`, `am.css`의 `@page A4 가로`, `body.am-printing`)은 그대로 쓰고, 문서 안 와이어프레임 부분만 `wire.js`로 바꾼다

## 3. 순서와 역할

| 순서 | 단계 | 크기 | 시작 조건 |
|---|---|---|---|
| 1 | D0 | 작음 | 승인 즉시 가능 (디자인 세션 파일만) |
| 2 | D1 → D2 → D3 | 작음·중간·작음 | 4차 종료 + 파일 넘겨받기 |
| 3 | D4 | 중간 | D2 후 (실행 취소 버튼 자리) |
| 4 | D5 | 큼 | D4 후 (목록·정렬·실행 취소 재사용) |
| 5 | D6 | 중간 | D5 후, 통합 세션과 함께 |

파일 소유: `hub.js`, `brief.js`, `page.js`, `am.css`는 통합 세션 소유. 제안: 4차가 끝나면 '디자인 차수' 동안 이 파일들을 디자인 세션이 넘겨받고(plans/09 4.1 절차), 새 파일 `editor.js`, `wire.js`, `history.js`는 디자인 세션이 만든다. 그동안 통합 세션은 이 파일들을 고치지 않는다.
