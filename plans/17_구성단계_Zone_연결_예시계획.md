# 02 구성 단계의 Zone 연결: 예시 계획 (초안, 사용자 검토 대기)

작성 2026-11-06. 표시: **[사실]** 데이터·코드로 확인 / **[가설]** 추정 / **[제안]** 결정 필요

## 0. 한 줄 요약

담당자가 Zone을 따로 고르게 하지 않는다. **구좌가 곧 Zone**이고, Zone은 '진열 유형 + 이름'으로 정리한다. 02 구성은 지난 비슷한 행사의 **진열 구성(Zone 순서·칸 수)** 을 레퍼런스로 골라 구좌 틀을 만드는 곳이 된다. 03 상품 행의 Zone 칸은 04에서 상품을 구좌에 넣을 때 자동으로 채워진다.

## 1. 지금 Zone이 하는 일과 문제

| | 내용 |
|---|---|
| [사실] 뜻 | PROMO_WORK '카테고리명'. 행사 페이지의 상품 진열 칸(탭·카드 묶음) 이름. 32개 행사 중 24개가 사용, 상시 행 69%·하루특가 행 8%에 기입 |
| [사실] 쓰는 모양 | 한 행사 안에서 순서대로, 칸마다 상품 수가 3·4·6개로 고름. 얼리버드 → 메인으로 구성을 그대로 재사용(추석, 설, 26추석) |
| [사실] 섞인 용도 | 진열 기준(가격대·취향·차 종류·큐레이션) + 혜택 방식(균일가 존, 혜택 02 쿠폰가, 상시 단품 35%_무카페인) + 요일(월 블렌디드~금 콤부) + 숨김(미노출) + 번호(선물 가이드 01, 1~8) |

| [사실] 툴 안의 역할 | ① 엑셀 내보내기 때 카테고리명 칸 값 ② 02 구성에서 구좌 ↔ 03 행을 잇는 다리(`page.js` `zone_tag`, Zone이 같은 행이 그 구좌 상품) |
| 문제 | 02에서 고를 수 있는 Zone은 지금 기획안 행에 적힌 것뿐이라 03에서 Zone을 먼저 적어야 함. 순서가 거꾸로이고, 담당자는 Zone을 두 번(03 칸, 02 연결) 다룸 |

## 2. 원칙 [제안]

1. **구좌 1개 = Zone 1개.** 구좌 상세에서 'Zone 연결' 선택 상자를 없애고, 구좌가 자기 Zone 이름을 가진다(기본값 = 구좌명).
2. **Zone은 '유형 + 이름'.** 유형은 정해진 목록에서 고르고(가격대, 취향·테마 …), 이름은 페이지에 보일 말 그대로 자유롭게 적는다.
3. **상품 행의 Zone은 자동.** 04에서 상품을 구좌에 넣으면 그 할인 행의 Zone 칸이 구좌의 Zone 이름이 된다. 03 표에서도 직접 고칠 수 있다(멘토님 툴 그대로).
4. **하루특가 띠는 Zone 없음.** 데이터상 하루특가 행은 92%가 Zone이 없다. 하루특가 구좌(`deal-banner`)는 지금처럼 하루특가 행 전체를 보여 준다.
5. **지난 구성은 틀만 가져온다.** Zone 순서·유형·칸 수만 가져오고, 상품은 '후보 상품'으로만 넣는다(바로 배치하지 않음). 상품·할인을 그대로 가져오는 건 기존 '지난 행사 상품·할인 가져오기'가 맡는다.

## 2-1. 탭(필터) 구좌 (사용자 추가 2026-11-06)

한 구좌 안에 알약 필터가 있고, 누르면 그 Zone의 상품으로 바뀌는 구좌. 예: '가격대별 선물 추천' 구좌 안에 2만원대 / 3-4만원대 / 5만원 이상. 가격대뿐 아니라 취향·차 종류·요일 등 모든 유형에 쓸 수 있다.

| | 내용 |
|---|---|
| [사실] 데이터 흔적 | 같은 유형의 Zone이 같은 칸 수로 이어지는 묶음이 많음: 설 `2만원대(4) 3-4만원대(4) 5만원 이상(4)`, 멤버십위크 차 종류 8개×4, 차의날 요일 5개×4(두 주), 미피 `1~4(2)` |
| [가설] | 위 묶음은 한 구좌 안의 필터 탭이었을 가능성이 높음. PROMO_WORK에는 Zone 이름만 남아 탭이었는지는 알 수 없음 → 행사 페이지 캡처·레퍼런스 수집분으로 확인 필요(엔지니어·수집 담당) |
| 원칙 [제안] | **구좌 1개 = Zone 1개**를 고쳐 **탭 1개 = Zone 1개**. 탭이 없는 구좌는 구좌 자체가 Zone 1개 |
| 구좌 형식 | 구좌 상세에 '상품 묶음 하나 / 필터 탭으로 나누기'. 탭 구좌의 진열 유형 = 탭을 나눈 기준 |
| 탭 편집 | 탭 이름(= PROMO_WORK 이름, 기본 같음), 순서 끌기, 탭마다 상품 칸 수, [+ 탭 추가], [탭을 따로 구좌로 나누기]. 탭이 없는 구좌에는 [같은 유형의 옆 구좌와 탭으로 묶기] |
| 지난 구성 가져오기 | 같은 유형 + 같은 칸 수로 이어진 Zone 2개 이상이면 묶음으로 보여 주고 '탭 구좌 1개로 / 구좌 N개로'를 고르게 함. 기본은 '탭 구좌 1개로'(가설 근거), 탭 구좌 이름은 '가격대별 선물 추천'처럼 유형 + '별 추천'으로 초안 |
| 미리보기·04 | 와이어프레임에 알약 줄. 누르면 그 탭의 상품 칸으로 바뀜. 04에서 상품은 지금 고른 탭에 넣고, 03 행 Zone = 탭 이름 |
| 확인 | 상품이 없는 탭('고객이 누르면 빈 화면이 보여요'), 탭이 1개뿐인 탭 구좌(묶음 하나로 바꾸기 제안) |
| 데이터 | 구좌에 `tabs: [{ tabId, label, zone_tag, cards }]` 추가. 탭이 없으면 지금처럼 구좌의 `zone_tag`. 구좌 카드(slot)에 `tabId` |
| 레이아웃 | 디자이너 레이아웃 7종에 탭이 없음. 새 레이아웃을 만들지 않고 상품 레이아웃(grid2·grid3·split)의 '필터 탭' 속성으로 둠 → `wire.js`가 알약 줄을 그림 |
| 05 내보내기 | 탭마다 카테고리명 하나. 미리보기 문서(PDF)는 탭 구좌를 '탭 이름별로 펼쳐서' 보여 줄지, 첫 탭만 보여 줄지 결정 필요 |

## 3. Zone 유형 (초안) [제안]

| 유형 | 예 (실제 표기) | 페이지에서의 뜻 |
|---|---|---|
| 가격대 | 2만원대, 3-4만원대, 5만원 이상, 1-2만원대, 가격대별 | 선물 예산별 고르기 |
| 취향·테마 | 달콤한, 은은한, 무카페인, 다양한(구성), 트렌디한, 하절 티 | 맛·상황으로 고르기 |
| 차 종류 | 말차, 허브, 블렌디드, 녹차/발효차, 잎차, 콤부차/콜드브루, 티푸드, 티웨어 | 카테고리로 고르기 |
| 큐레이션 | 인기템, 재구매한, 리뷰가 좋은, 급상승한, 새로 오픈한, 카트에 담은 | 판매 신호로 고르기 |
| 포장·구성 | 보자기(브라운·화이트·핑크), 10입, 20입, 보틀&쇼핑백, PRESTIGE | 포장·구성으로 고르기 |
| 혜택 방식 | 균일가 존, 혜택 02 할인가/쿠폰가, 2+1, 단품할인, 정율, 정액, 5000 페이백 | 혜택이 칸의 기준 |
| 요일 | 월 블렌디드, 화 허브, 수 녹차·발효차, 목 말차·밀크티, 금 콤부·콜드브루 | 요일별 편성 |
| 페이지 번호 | 선물 가이드 01~03, 1~8, ○○ ROOM | 이름만으로 뜻을 알 수 없음 → 유형을 직접 고르게 함 |
| 숨김 | 미노출 | 페이지에 안 보이는 행 |

- 표기 정리(같은 뜻 합치기)는 처음엔 규칙 몇 개(공백 무시, '2만원/2만원대', '리뷰가 좋은/리뷰좋은/후기가좋은')로 **DEMO**로 보여 주고, 실제 정리 사전과 자동 분류는 엔지니어 검증 항목으로 넘긴다(plans/16에 Z1~Z3 추가 예정).
- 한 Zone이 두 유형에 걸치면(예: '상시 단품 35%_무카페인' = 혜택 방식 + 취향) 첫째 유형만 고르고 나머지는 이름에 남긴다.

- 첫 구좌는 메인 비주얼(hero), 끝은 하루특가 띠가 있으면 deal-banner를 붙일지 묻는다.
- 지난 상품은 '후보 상품'에 넣을지 한 번 묻는다(체크 상자, 기본 끔).

## 6. 단계와 일정

- 이 계획은 plans/15의 **R5(02 구성)** 안에서 한다. R4(제안 출처 모듈)의 `outline.js`·`references.js` 자리에 '지난 진열 구성'을 DEMO 규칙으로 넣는다.

## 7. 정해 주실 것

1. Zone 유형 목록(3장)이 담당자 감각과 맞는지, 빼거나 더할 유형
2. 지난 구성을 가져올 때 상품도 후보 상품으로 넣을지(기본 끔 제안)
3. 03 표의 Zone 칸을 계속 직접 고칠 수 있게 둘지(제안: 둠, 04와 다르면 확인 띄움)
4. ~~05 미리보기에서 탭 구좌 보여 주기~~ → 결정: 첫 탭만 보여 주고, 미리보기 문서에서도 다른 탭을 누르면 바뀌는 걸 볼 수 있게 (R8, `wire.js` `switchWireTab`)
5. 지난 구성의 묶음 기본값 → **사용자 고민 중**. 구현은 '탭 구좌 1개로'가 기본이고 묶음마다 바로 바꿀 수 있음
6. ~~유형 목록~~ → 결정: 목록 동의. 새 유형 추가·이름 수정 가능하게 (R5 반영. 지금은 그 기획안 안에서만 남음)
