## 2. 프론트의 '제안 출처' 설계 (AI·추천을 나중에 붙이기 쉽게)
화면은 데이터를 직접 만들지 않고 아래 **출처 모듈**에 물어본다. 지금은 예시(DEMO) 출처를 쓰고, 엔지니어가 실제 출처를 만들면 그 모듈만 바꾼다.

| 출처 모듈 (새 파일 `js/am/sources/`) | 지금 (DEMO) | 나중 (연동 예정, 미확정) | 화면 |
|---|---|---|---|
| `copy.js` 대표 카피·구좌 문구 제안 | 브리프의 명분·콘셉트·목적으로 규칙 문장 몇 개 | AI(로컬 Claude Code / 다른 모델, 미정), 카피 사례(예: 29cm 수집분) 참고 | 02 대표 카피, 04 구좌 문구 초안 |
| `outline.js` 구좌 구성안 제안 | 지금 ③의 목적별 기본 구성·Zone 초안 규칙 | AI·규칙 조합 | 02 구성안 |
| `references.js` 레퍼런스 목록·상세·전체 페이지 | 디자이너 예시 레퍼런스(가상 이미지, '예시' 표시) | 원본 HTML·캡처 수집, 구좌 분리, 태깅 (엔지니어) | 레퍼런스, 02, 04 |
| `recommend.js` 구좌별 레퍼런스 추천 | 구좌 역할·레이아웃이 맞는 예시를 순서대로 (점수 없음, '시연용 순위' 표시) | 조건 검색 + 의미 기반 추천, 추천 이유 | 02, 04 |

모든 출처 결과에는 `mode: 'demo' | 'live'`와 `basis`(무엇을 근거로 만들었는지)를 붙이고, 화면은 `demo`면 '예시예요' 띠를 늘 보여준다. 적합도·성과처럼 근거 없는 숫자는 그리지 않는다.

## 4-1. 04 구좌 편집의 상품·가격 규칙 (사용자 결정 2026-11-06: 04에서도 할인을 바꾸고, 구좌별 상품을 고른다)

디자이너의 '가격 초안 → 명시적 적용' 흐름을 따르고, 값은 03 상품·혜택의 할인 행 하나에만 둔다(두 곳에 따로 저장하지 않음).

| 상황 | 동작 |
|---|---|
| 구좌에 상품 고르기·바꾸기 | 상품 찾기 드로어 → 상품 상세 → [이 카드에 연결하기]. 카드(`slotId`)와 소개 문구는 그대로, 상품만 바뀜. 실행 취소 가능 |
| 할인율 미리보기 | 상품·가격 탭에서 할인율을 넣으면 '적용할 행사 판매가'가 바로 계산됨. 이때는 **아무것도 저장하지 않음**('아직 기획안에 적용하지 않았어요') |
| [가격 적용하기] | 03의 그 상품 **상시 할인 행** 할인율을 바꾸고 저장. 알림 '기획안에 행사 가격을 적용했어요. 실제 판매 가격은 바뀌지 않아요' |
| 그 상품의 상시 행이 여러 개(기간이 다름) | 어느 행에 적용할지 고르게 함(기간 표시). 기본은 기획안 기간과 겹치는 행 |
| 그 상품의 할인 행이 없음 | [가격 적용하기]가 새 상시 행을 만듦: 기획안 기간, 구좌의 Zone, 기획안 이름. [할인 없이 두기]는 '할인 없음'(큐레이션) 행을 만듦 |
| 하루특가 행 | 04에서는 바꾸지 않음. 하루특가 구좌는 날짜별 상품을 보여주고 [하루특가 편성 열기]로 03에 감 |
| 원가율 기준 넘음 | 03과 같은 검증. 적용은 막지 않고 '원가율 45%를 넘어요' 주의를 함께 보여줌 |
| 03에 저장하지 않은 편집이 있음 | 04에서 적용하기 전에 '03 상품·혜택에 저장하지 않은 변경이 있어요'를 묻고(닫기 / 03으로 가기) 덮어쓰지 않음 |
| 적용하지 않은 채 다른 구좌·단계로 이동 | 확인창: [닫기] [변경한 가격 버리고 이동] [가격 적용하고 이동] |
| [가격 되돌리기] | 초안만 지금 기획안 값으로 돌림 |
| 실행 취소 | 구좌 편집의 실행 취소는 페이지(구좌·문구·상품 연결)만. 가격 적용은 대상이 아님(디자이너와 같음). 되돌리려면 할인율을 다시 적용 |
