## 1. 지금 실제로 있는 것 (코드 확인)
- **실행 환경**: 멘토님 '프로모션 기획 도우미' 복사본(`workspace/amoread_app`). FastAPI, `127.0.0.1`에만 바인딩, 실행마다 바뀌는 토큰(`X-Planner-Token`), Host 검사, CSP `default-src 'self'`(인라인 스크립트·스타일 불가). 개인 PC 1인 사용 전제
- **데이터 원천 (읽기만)**: 판매실적 CSV, PROMO_WORK·SEQ_MASTER 엑셀(샘플), 상품장 엑셀(원가는 가상 값) → `planner/build.py`가 `planner_data.json` 생성. 원천 파일에는 쓰지 않음
- **기획안 저장**: `planner/data/projects/{32자리 hex}.json` 파일 하나가 기획안 하나. 임시 파일 후 교체 방식으로 저장. 스키마 버전 1. 계정·공유 없음
- **AMOREAD API** (`amoread/api.py`, 접두사 `/api/am`): `GET/POST /projects`, `GET /projects/{pid}`, `POST /projects/{pid}/delete`, `POST /projects/{pid}/confirm`, `GET /projects/{pid}/result`, `GET /legacy`, `POST /legacy/{id}/import`, `GET /calendar`, `GET /day`, `POST /seasons/add`, `GET /concepts`, `GET /schedule`, `POST /check`, `POST /export`
- **AI (멘토님 툴)**: `planner/claude_agent.py`가 `claude_agent_sdk`로 로컬 Claude를 부름. 도구(tool) 정의 + JSON 스키마 출력, 비동기 작업(`POST /api/claude/plan` → `GET /api/claude/job/{id}` 폴링), 모델 이름은 `config.CLAUDE_MODEL`. 실데이터로 써도 되는지 승인은 확인되지 않음
- **기획안 데이터 모양** (`api.py` `ProjectReq`): `brief`(명분, 컨셉, 목적, 타깃, 고객 상황, 목표, 기간, 페이지 유형, 배경, 조건, 혜택 메모, 명분 사전 연결), `promo_rows`(PROMO_WORK 행과 같은 필드: 프로모션명, 유형 상시/하루특가/큐레이션, 시작·종료, SEQ 또는 조합, 할인율, 소구, Zone, 털이, 메모), `deal_plan`(하루 자리 수, 후보), `pool`(역할 미정 후보), `page.sections[]`(아래 3장), `links`(예전 기획안 ID, PROMO_WORK 키), `status`(기획 중/확정/반영됨), `snapshot`(확정 시점 예측)

### 2.4 AI 제안 [AI 엔지니어]
프론트는 아래 요청·응답 모양을 가정하고 지금은 예시(DEMO)로 채웁니다. 같은 모양이면 프론트를 고치지 않고 연결할 수 있습니다.
```
대표 카피 제안   요청 { brief, tone?, avoid[] }            응답 { items[{text, basis}], mode, model?, sources[] }
구좌 구성안      요청 { brief, promoRows?, pageKind }       응답 { sections[{name, role, layoutId, reason}], mode }
구좌 문구 초안   요청 { brief, section, products[] }        응답 { headline, subhead, cta, basis, mode }
레퍼런스 추천    요청 { brief, section(role, layout), k }   응답 { items[{referenceId, reason, scoreKind: 'demo'|'experimental'}], mode }
```
| # | 질문 |
|---|---|
| A1 | 호출 방식: 멘토님 툴처럼 로컬 Claude Code(Claude Agent SDK)를 쓸지, 서버 API를 쓸지. 사내 보안 정책상 허용 범위 |
| A2 | 응답 시간: 즉시 응답인지, 멘토님 툴처럼 작업 시작 → 폴링인지 (프론트의 '만드는 중' 상태 설계에 필요) |
| A3 | 카피 사례(예: 29cm 수집분) 활용 방법: 검색해 참고로 보여줄지, 생성 근거로만 쓸지. 외부 카피를 그대로 쓰지 않도록 하는 장치 |
| A4 | 근거 표시: 어떤 브리프 항목·사례를 썼는지 응답에 담을 수 있는지 (프론트는 `basis`, `sources`를 화면에 보여줌) |
| A5 | 금지 표현(식품 효능 암시 등) 검사: AI가 보조할지, 규칙 사전으로 할지. 지금 멘토님 툴에 `efficacy_flags`(규칙)가 있음 |
| A6 | 일부만 다시 제안: 구좌 하나·카피 하나만 다시 받고 나머지는 그대로 두는 것이 가능한지 |
| A7 | AI에 넘겨도 되는 데이터 범위: 원가·매출(가상/실제), 고객 리뷰 등 |

## 3. 기획 구좌(PlannedSection) 지금 모양
```
section { sectionId, order, name, purpose(구좌 목표), role(넣은 이유), zone_tag(PROMO_WORK 카테고리명),
          layoutId, layoutSourceRefId, headline, subhead, cta,
          slots[{ slotId, seq | items[{seq, qty}], placeholderStatus: AVAILABLE|UNDECIDED, customCopy }],
          designNotes, designerReferences[{referenceId, designerNote}], unplacedProducts[], price_display, section_price }
```
- 구좌 순서를 바꿔도 `sectionId`·`slotId`와 그 안의 문구·상품·요청사항은 함께 움직입니다(프론트 단위 시험 있음)
- 슬롯의 상품을 바꾸면 `slotId`와 `customCopy`는 그대로, 상품만 바뀝니다
