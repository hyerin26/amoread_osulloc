# 레퍼런스에 '탭으로 상품을 나눈 구좌' 분류 넣기 — 개발 요청 spec (2026-11-16)

> 요청: 이미 수집한 레퍼런스와 앞으로 수집할 레퍼런스에서 **탭(가격대·카테고리·취향 등)으로 상품을 나눈 구좌**를 알아보고 표시해 주세요.
> 목적: 02 구좌 구성의 **C안(레퍼런스 조합 추천)**도 탭 구좌를 추천할 수 있게 하는 것.
> 관련: plans/28 (탭 구좌 02·03·A안 구현, `merge/2026-11-15`에 반영됨)

## 1. 왜 필요한가

| | 지금 | 이 작업 뒤 |
|---|---|---|
| 02 고른 구성·03 편집기 | 탭 구좌를 만들고 고칠 수 있음 (plans/28 1~3단계) | 같음 |
| 추천 A안 (유형 규칙) | 규칙형 탭 구좌 추천 (선물 → 가격대 탭, 키워드 2개 이상 → 키워드 탭) | 같음 |
| **추천 C안 (레퍼런스 조합)** | **탭 구좌를 추천하지 못함** — 레퍼런스에 '탭 구좌'라는 분류가 없음 | 브리프에 맞는 탭 구좌 레퍼런스를 찾으면 탭 구좌로 추천하고 출처를 보여 줌 |
| 레퍼런스 라이브러리 | 탭 구좌만 모아 볼 수 없음 | '탭 구좌' 필터로 사례를 모아 봄 |

- 실제 행사 페이지에는 가격대별·카테고리별·취향별 탭 구좌가 흔합니다. 우리 기획에서도 **탭 하나 = PROMO_WORK Zone 하나**라서, 탭 구좌는 할인 행·상품 배치와 바로 이어지는 중요한 구좌입니다.
- C안은 수집한 실제 사례로 구성을 짜는 안이라, 탭 구좌 사례가 많을수록 쓸모가 큽니다. 지금은 C안을 고른 담당자가 탭 구좌를 매번 직접 만들어야 합니다.

## 2. 지금 데이터 상태 (2026-11-16, `planner/data/ai_refs/sections.jsonl`)

- 구좌 **788개**, 역할(`role`) **19종**. '탭으로 상품을 나눈 구좌'를 뜻하는 역할이나 속성은 **없음**.
  - 가장 가까운 것은 `section_navigation`(페이지 안 바로가기 탭)인데, 이것은 상품을 나누는 탭이 아닙니다.
- 글(`text`)에 탭 비슷한 말(탭·전체보기·카테고리별·가격대별·만원대·취향별·테마별·필터)이 들어간 구좌는 **92개**이고, 그중 `product_list`가 65개입니다.
  - 하지만 대부분은 '전체보기'(더 보기 링크)라서, **글 규칙만으로 판정하면 틀린 것이 많습니다**.
- **한 탭 구좌가 탭마다 따로 수집된 사례**도 있습니다. 예: `dongwonmall-001`의 `s12` '우유/유음료', `s13` '치즈'는 원래 한 구좌의 탭일 가능성이 높습니다.
  - 이대로면 C안이 탭 하나만 떼어 와 일반 상품 구좌처럼 추천합니다.
- 역할은 `amoread/ai/roles.py`의 글 정규식으로, 구좌 종류(`stype`)는 `amoread/ai/labeling.py`에서 정해집니다. 둘 다 규칙 기반이고 외부 호출이 없습니다.
- 수집할 때 화면 HTML·배치를 저장한 페이지(`planner/data/ai_refs_user/capture`, 레퍼런스의 `cap`)는 화면 구조 단서를 쓸 수 있습니다.

## 3. 요청 내용

### 3-1. 분류 모양: 역할(role)은 그대로, 탭은 속성으로
앱의 저장 형식과 같게 갑니다. 앱에서 탭은 구좌 종류가 아니라 구좌에 붙는 속성입니다(`page.sections[].tabs`). 그래서 레퍼런스 구좌에도 `role`과 따로 아래 속성을 붙여 주세요.

```json
{
  "id": "dongwonmall-001:s12",
  "role": "product_list",
  "tabs": {
    "is_tab": true,
    "kind": "카테고리",
    "labels": ["우유/유음료", "치즈", "요거트"],
    "group": "dongwonmall-001:tg1",
    "basis": "dom",
    "confidence": "high",
    "labeled_by": "auto-v1"
  }
}
```

| 필드 | 뜻 |
|---|---|
| `is_tab` | 탭으로 상품을 나눈 구좌인지 |
| `kind` | `가격대` · `카테고리` · `취향·테마` · `기타` (앱의 진열 유형 `zone_kind` 어휘와 같게) |
| `labels` | 원본 페이지의 탭 이름 (최대 12개, 각 40자. 앱 `Tab.label` 제한과 같음) |
| `group` | 탭마다 따로 수집된 구좌를 하나로 묶는 열쇠 (같은 페이지·연속한 구좌) |
| `basis` | 판정 근거: `dom`(화면 구조) · `text`(글) · `wire`(와이어프레임) · `human`(사람이 고침) |
| `confidence` | `high` · `medium` · `low` |
| `labeled_by` | 기존 라벨과 같은 규칙 (`auto-v1` / `human`) |

### 3-2. 판별 단서 (제안 — 더 나은 방법이 있으면 그쪽으로)
1. **화면 구조 (가장 믿을 만함):** 캡처한 HTML에서 상품 그리드 바로 위에 아래 특징이 있는 경우입니다.
   - `role="tablist"`·`aria-selected` 같은 속성, 또는 class에 `tab`·`filter`·`category`가 들어간 요소
   - 짧은 글(대략 10자 이하) 버튼이나 링크가 **3~12개** 한 줄로 반복됨
2. **글 (보조):**
   - 가격대 표현: `n만원대`, `n만원 이하`, `~n원`
   - '가격대별·카테고리별·취향별·테마별'
   - **'전체보기'·'더보기'만 있는 것은 탭이 아님** (지금 데이터에서 틀린 판정의 대부분)
3. **와이어프레임:** 아직 합치지 않은 `ai_yewon` 브랜치에 구좌 템플릿 분류(17개 유형, `nav-tabs` 등)와 와이어프레임 추출기(`amoread/ai/wireframes.py`)가 있습니다. 재사용할 수 있는지 봐 주세요.
4. **쪼개진 탭 묶기:** 같은 페이지에서 연속한 `product_list` 구좌의 제목이 짧은 탭 이름 같고, 상품 진열 모양이 같으면 같은 `group`으로 묶어 주세요.

### 3-3. 적용 범위
- **이미 수집한 레퍼런스 (일괄):** 788개 구좌에 한 번 돌리고, 결과를 사람이 검토할 수 있게 CSV로 내보내 주세요. 지금 `labeling.export_csv` / `import_overrides`와 같은 방식이면 됩니다.
- **앞으로 수집할 레퍼런스 (자동):** 새 페이지를 넣을 때 같은 판정 함수를 부르게 해 주세요. 지금 라벨을 붙이는 자리는 `amoread/ai/intake.py`(새 페이지, `classify_page` 약 292행·구좌 행 약 393행)와 `amoread/ai/build_index.py`(색인 다시 만들기, 약 90·113행)입니다.
- **사람이 고친 값 우선:** `label_overrides.json`에 탭 속성도 담아서, 색인을 다시 만들어도 사람이 고친 값이 남게 해 주세요.

### 3-4. 쓰는 곳
- **추천 C안 (`amoread/ai/compose.py` `build`):** 고른 레퍼런스가 `is_tab`이면 `secs` 넷째 칸에 `{src, refId, sx, kind, tabs, note}`를 함께 넣어 주세요.
  - 화면(`planner/static/v2/compose.js` `toRows`)은 이미 `kind`·`tabs`·`note`를 읽어 탭 구좌로 받습니다. 화면 쪽은 고칠 필요가 없습니다.
  - `note`에는 '레퍼런스 탭 구조'처럼 출처를 적어 주세요. 02에서 탭 구좌 줄에 그대로 보입니다.
- **레퍼런스 라이브러리:** 카드에 '탭 구좌 · 카테고리 3개' 표시와 '탭 구좌' 필터를 넣어 주세요.
- **레퍼런스 추천 (03 편집기):** 탭 구좌를 편집 중이면 탭 구좌 레퍼런스를 앞에 보여 주세요(선택).

## 4. 완료 기준
- [ ] 기존 788개 구좌에 탭 속성이 붙고, 검토용 CSV가 나온다
- [ ] 표본 검수: '탭 구좌'로 판정한 것 중 사람이 맞다고 한 비율 **90% 이상**. '전체보기'만 있는 구좌는 탭으로 판정하지 않는다
- [ ] 쪼개진 탭(예: `dongwonmall-001` s12·s13)이 같은 `group`으로 묶인다
- [ ] 새로 수집한 페이지에 자동으로 붙는다. 사람이 고친 값은 색인을 다시 만들어도 남는다
- [ ] C안: 탭 구좌 레퍼런스가 브리프에 맞으면 탭 구좌로 추천되고, 02에서 탭 이름·출처가 보인다
- [ ] 테스트: 판정 단서별 단위 테스트(맞는 예, '전체보기' 같은 틀리기 쉬운 예), C안 탭 구좌 테스트 (`tests/test_ai_refs_compose.py`의 `TabRule`과 같은 방식)

## 5. 하지 않는 것
- 기존 역할(`role`) 체계 바꾸기 — 탭은 따로 붙는 속성입니다
- 판정에 AI 모델 호출 — 지금 라벨링처럼 규칙 기반으로 (외부 호출 없이, 다시 돌려도 같은 결과)
- 탭 안의 상품 목록 추출 — 이번에는 '탭 구좌인지 · 어떤 탭인지'까지만

## 6. 같이 정할 것 (개발자 의견 부탁)
1. **C안이 탭 구좌를 가져올 때 탭 이름:** 원본 페이지의 탭 이름을 그대로 쓸지, 이번 브리프(가격대·키워드)로 새로 만들지. 기획자 쪽 의견은 "구조는 레퍼런스를 따르고, 이름은 브리프에 맞게 바꾸되 원본 이름은 출처로 보여 주기"입니다.
2. **판정 기준값:** `confidence`가 `low`인 것도 C안에 쓸지, 라이브러리 표시만 할지.
3. **검수 담당·일정:** 일괄 판정 CSV를 누가 언제 검토할지.
