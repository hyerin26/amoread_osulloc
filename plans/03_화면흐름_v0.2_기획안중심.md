# 화면 흐름 v0.2: 기획안 중심 구조 (검증용 초안)

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-11-05 |
| 상태 | **검증 전 초안.** 사용자와 항목별로 확인한 뒤 구현한다 |
| 결정 | A안: 기획안 하나에 모든 담기가 모이고, 작업대는 기획안 안의 '상품·할인' 단계로 흡수한다 |
| 바뀌는 이유 | 1단계 결과가 두 툴을 묶어 놓기만 한 구조였음. 기획안이 두 종류, 작업대 역할 불분명, 담기 33곳이 작업대로 감, 화면 사이를 튕겨 다님 |

## 1. 쓰는 말 (화면에 보이는 용어)

| 용어 | 뜻 | 쓰지 않는 말 |
|---|---|---|
| 기획안 | 프로모션 하나를 기획하는 단위. 명분, 기간, 할인 상품, 페이지가 모두 여기 담긴다 | 작업대, 통합 기획안, 프로젝트 |
| 작업 중 기획안 | 지금 열어 둔 기획안. 상단에 늘 보이고, 어디서 담기를 누르든 여기로 들어간다 | 연결, 연결 끊기 |
| 단계 | 기획안 안의 작업 구역 5개. 순서대로 하지 않아도 된다 | 탭 |
| 담기 | 다른 화면에서 고른 상품이나 행을 작업 중 기획안에 넣는 것 | 작업대로 불러오기 |
| 참고 자료 | 판단 근거를 보는 화면(상품, 지난 성과, 트렌드, 레퍼런스). 여기서는 담기만 한다 | 근거 탭 |

## 2. 전체 구조

```
상단  [AMOREAD]  캘린더 · 기획안 · 참고 자료 ▾        [작업 중: 입동 기획 · 상품 8 · 섹션 5 ▾]   ⚙
                                  └ 상품, 지난 성과, 트렌드, 레퍼런스(추후)

기획안 화면
┌──────────────────────────────────────────────────────────────────────────────┐
│ 입동 기획   12/01~12/25 · D-26 · 이벤트 페이지                 기획 중 ▾   저장됨 │
├──────────────────────────────────────────────────────────────────────────────┤
│ ① 명분·브리프 준비됨 │ ② 상품·할인 8개, 주의 2 │ ③ 페이지 구성 5섹션 │ ④ 구좌 편집 │ ⑤ 확인·전달 │
├────────────────────────────────────────────────────┬─────────────────────────┤
│ 지금 단계의 작업 영역                              │ 다음에 할 일             │
│                                                    │  · 상품 3개가 페이지에   │
│                                                    │    아직 없어요 [배치하기]│
│                                                    │ 근거                     │
│                                                    │  · 명분, 작년 같은 행사  │
└────────────────────────────────────────────────────┴─────────────────────────┘
```

- **작업 중 기획안 칩**(상단 오른쪽): 누르면 최근 기획안 목록과 `새 기획안`. 어느 화면에서든 지금 무엇에 담기는지 보인다.
- **단계 막대**: 단계마다 상태를 보여준다. 잠그지 않으므로 어느 단계든 바로 갈 수 있다.
- **다음에 할 일**(오른쪽 패널): 단계끼리 맞지 않는 곳을 찾아 안내한다. 단계 사이의 연결은 이 패널이 맡는다 (5장).

## 3. 시작 입구: 어디서 시작해도 결과는 기획안 하나

| 입구 | 위치 | 만들어지는 기획안 | 처음 열리는 단계 |
|---|---|---|---|
| 명분에서 | 캘린더 명분 카드 `이 명분으로 기획 시작` | 명분, 기간, 씨앗, 명분 사전 연결 | ① 명분·브리프 |
| 빈 기획 | 기획안 목록 `새 기획안` | 빈 브리프 | ① 명분·브리프 |
| 지난 행사에서 | 기획안 목록의 `지난 행사 상품·할인 가져오기` | 지난 행사의 상품·할인율을 올해 날짜로 옮긴 행, 행사 이름 (새 기획안) | ② 상품·할인 |
| 지난 회차에서 | 참고 자료 › 지난 성과 회차 `이 상품 구성으로 새 기획안 만들기` | 같음 (새 기획안) | ② 상품·할인 |
| 하루특가 빈 날에서 | 캘린더 날짜 상세 후보 `담기` | 작업 중 기획안이 없으면 '페이지 없음' 기획안을 새로 만들어 담음 | 그대로 캘린더에 머묾 |
| 아이디어·트렌드에서 | 아이디어, 트렌드 기획전 `기획안으로 만들기` | 제안된 행과 근거 | ② 상품·할인 |

- 기획안에는 **어디서 시작했는지**를 기록한다(기존 `origin`).
- 명분 없이 시작한 기획안은 ①이 '명분 없음'으로 표시되고, 다음에 할 일에 "명분과 컨셉을 정해 보세요"가 뜬다. 할인부터 시작해도 결국 명분을 챙기게 된다.

## 4. 단계별 화면

### ① 명분·브리프
- 답하는 질문: 왜 지금, 누구에게, 무엇을, 언제
- 내용: 지금의 브리프 화면 그대로(명분, 컨셉, 목적, 타깃, 고객 상황, 목표, 기간, 페이지 유형, 배경, 조건, 혜택)
- 바뀌는 점: 작업대의 '기획 메모'(명분, 컨셉, 고객, 목표)는 **이 단계 하나로 합친다.** 같은 내용을 두 곳에 쓰지 않는다
- 옆 패널: 명분 근거, 최근 쓴 명분·컨셉, 캘린더 반영
- 상태: 명분 없음 / 작성 중 / 준비됨(명분, 컨셉, 기간이 있음)

### ② 상품·할인 (작업대가 들어오는 곳)
- 답하는 질문: 무엇을, 얼마에, 언제 할인하나
- 내용: 지금 작업대의 표와 기능을 **그대로 이 안에 둔다**

| 지금 작업대 | 바뀐 위치 |
|---|---|
| 행 표, 판정 배지, 고치기 | ② 본문 |
| 개요 띠(리본, 숫자 4개) | ② 본문 위 |
| `+ 행 추가`, `묶음 추천`, 정렬 | ② 도구 막대 |
| `작년 행사 다시 하기` | ② 도구 막대 `지난 행사 상품·할인 가져오기` (이름 변경, 아래 설명) |
| `Claude에게 수정 요청` | ② 도구 막대 (AI는 기존 동작 유지, 실데이터 승인 전까지 사용 자제) |
| 같은 기간 이미 잡힌 행사 | ② 옆 패널 근거 |
| 기획 메모 | ① 단계로 이동 |
| 제목 입력 | 기획안 머리 제목 하나로 통일 |
| `새 기획안`, `불러오기` | 기획안 목록, 작업 중 기획안 칩 |
| `저장` | 자동 저장 (버튼 없앰) |
| `확정` | 기획안 상태 '확정' (예측 스냅샷 함께 저장) |
| `공유 요약`, `엑셀 내보내기` | ⑤ 확인·전달 |

- 상태: 비어 있음 / 작성 중(오류 N, 주의 N) / 준비됨(행 1개 이상, 오류 0)

#### `지난 행사 상품·할인 가져오기` (확정 2026-11-05, 기존 '작년 행사 다시 하기')
- 이름을 하는 일 그대로 바꾼다. 기존 이름은 컨셉까지 가져오는지, 작년 행사만 되는지 헷갈렸음
- 실제 동작 (`replan.py refresh`, 바꾸지 않음)
  - 가져와요: 상품(SEQ), 할인율, 상시·하루특가 구분, 날짜 간격(364일 뒤 같은 요일), 행사 이름, Zone
  - 자동으로 바꿔요: 최근 90일 판매 없는 상품은 같은 카테고리·가격대로 교체(할인율 유지), 할인 0% 행 제외, 요즘 뜬 상품 일부 추가
  - 가져오지 않아요: 명분, 컨셉, 소구문구, 페이지 구성
  - 대상: 이름으로 찾은 가장 최근에 끝난 같은 이름 행사 (작년으로 정해져 있지 않음)
- 버튼 아래에 '가져와요'와 '가져오지 않아요'를 두 줄로 늘 보여준다
- 미리보기(유지, 교체, 제외, 추가, 확인해 볼 것)를 거쳐 **지금 기획안에 채운다.** 할인 행이 이미 있으면 `기존 행에 추가` / `기존 행 바꾸기`를 묻는다
- 지난 컨셉은 가져오지 않고 ① 명분·브리프의 '최근 쓴 명분·컨셉', '지난 같은 명분 행사'에서 참고만 한다
- 지난 기획안의 페이지 구성 가져오기는 추후 기능 (`plans/04_추후기능_지난기획안_페이지구성_가져오기.md`)

### ③ 페이지 구성
- 답하는 질문: 페이지를 어떤 섹션으로, 어떤 순서로 보여주나
- 내용: 지금의 페이지 구성 화면 (시작 방법 3가지, 섹션 순서·목표·레이아웃·Zone·상품·디자인 요청)
- 바뀌는 점: ②의 상품과 ③의 섹션 상품을 **양쪽에서 서로 보이게** 한다
  - ③에서 섹션별로 "할인 행에 있는 상품"과 "할인 행에 없는 상품(가격 미정)"을 구분해 보여준다
  - ②의 표에 열 하나를 추가해 각 상품이 어느 섹션에 놓였는지(또는 미배치) 보여준다
- 상태: 해당 없음(페이지 없음) / 비어 있음 / 작성 중 / 준비됨(섹션 1개 이상, 할인 상품이 모두 배치됨)

### ④ 구좌 편집 (다음 구현)
- 답하는 질문: 고객에게 실제로 어떻게 보이나 (카피, 상품 카드, 가격 노출, CTA)
- 가격은 ②의 할인율과 같은 값을 쓴다 (따로 저장하지 않음)

### ⑤ 확인·전달
- 답하는 질문: 내보내도 되나, 누구에게 무엇을 넘기나
- 내용: 확인할 것 모음(②의 오류·주의, ③④의 미정 항목, 단계 사이 불일치) → `확정` → 출력 3가지
  - PROMO_WORK 붙여넣기 엑셀 (기존 그대로)
  - 디자이너 기획안 (지금은 텍스트 브리프, ④ 구현 후 PDF)
  - 팀 공유 요약 (기존 그대로)

## 5. 단계 사이 연결: '다음에 할 일' 규칙

오른쪽 패널이 아래 순서로 확인해 위에서부터 최대 3개를 보여준다. 누르면 해당 단계의 해당 위치로 간다.

| 순서 | 조건 | 문구 예 | 가는 곳 |
|---|---|---|---|
| 1 | 명분 없음 | 명분과 컨셉을 정해 보세요 | ① |
| 2 | 기간 없음 | 기간을 정하면 캘린더와 제작 일정에 보여요 | ① 기간 |
| 3 | ② 오류 있음 | 할인 행 오류 2건이 있어요 | ② 첫 오류 행 |
| 4 | 페이지가 있고, 할인 상품 중 섹션에 없는 것이 있음 | 할인 상품 3개가 페이지에 아직 없어요 | ③ 배치 |
| 5 | 섹션 상품 중 할인 행에 없는 것이 있음 | 가격이 정해지지 않은 상품 2개가 있어요 | ② 행 추가 |
| 6 | 브리프 기간과 할인 행 기간이 다름 | 할인 기간(12/03~12/20)이 브리프 기간과 달라요 | ① 또는 ② |
| 7 | 제작 일정의 다음 마감이 3업무일 안 | 틀 기획 마감이 11/16이에요 | 개요 일정 |
| 8 | 위가 모두 없음 | 확인·전달에서 내보낼 수 있어요 | ⑤ |

- 개요 탭은 없애고, 머리(기간, D-day, 상태)와 오른쪽 패널(다음에 할 일, 제작 일정)로 나눠 담는다.

## 6. 담기 규칙 (지금 33곳의 바뀐 목적지)

| 담기 종류 | 지금 있는 곳 | 작업 중 기획안이 있을 때 | 작업 중 기획안이 없을 때 |
|---|---|---|---|
| 행 하나 담기 | 상품 표·상품 상세, 캘린더 하루특가 후보, 조합 추천, 리뷰 신호, 대화창 빠른 담기 | 그 기획안 ②에 행 추가. 알림: "입동 기획에 담았어요 [보기]" | "어느 기획안에 담을까요?" 최근 기획안 목록과 `새 기획안` |
| 기획안 통째로 | 지난 회차 다시 기획, 이번 주 아이디어, 트렌드 기획전, AI 기획 결과 (기획안 밖에서 누른 경우) | 세 가지 중 고름: `새 기획안으로 만들기`(기본) / `작업 중 기획안에 행 추가` / `작업 중 기획안의 행 바꾸기` | 바로 새 기획안으로 만듦 |
| 기획안 안에서 채우기 | ② 단계의 `지난 행사 상품·할인 가져오기` | 지금 기획안에 채움. 할인 행이 있으면 `기존 행에 추가` / `기존 행 바꾸기` | 해당 없음 (기획안 안에서만 보임) |

- 기준은 **누른 위치**다. 기획안 안에서 누르면 그 기획안을 채우고, 밖에서 누르면 새 기획안이 기본이다 (확정 2026-11-05)
| 행 추가 | AI 결과 `현재 기획안에 추가` | 그 기획안 ②에 행 추가 | 새 기획안으로 만듦 |

- 담은 뒤 **화면을 강제로 옮기지 않는다.** 지금은 담기마다 작업대로 튕겨 나가지만, 바꾼 뒤에는 알림의 `보기`를 눌러야 이동한다. 참고 자료를 계속 둘러보며 여러 개를 담을 수 있다.
- 상단 칩의 숫자(상품 8)가 바로 늘어나 담겼음을 확인할 수 있다.

## 7. 캘린더와 첫 화면

- **첫 화면은 캘린더로 한다.** 지금의 '이번 주'는 따로 두지 않고, 캘린더 오른쪽 패널로 옮긴다.
  - 이어서 하기: 최근 기획안 3개 (상태, 다음에 할 일 1줄)
  - 할 일: 하루특가 빈 날, 준비 시작이 다가온 명분, 곧 끝나는 행사 (기존 알림 규칙)
  - 이번 주 아이디어: 입구로 사용 (`기획안으로 만들기`)
- 캘린더 겹: 내 기획안 / 명분 / 잡힌 행사 / 공휴일. '작업대의 지금 행' 겹은 없앤다 (작업대가 없어지므로).

## 12. 하루특가 구조 (확정 2026-11-05)

**사용자 관찰 (멘토님께 들은 내용, 세부는 인터뷰로 확인)**
- 하루특가는 홈페이지의 별도 지면보다 **프로모션 페이지 안의 한 섹션**으로 들어가는 경우가 일반적

**구조**
- ② 상품·할인은 세 구역: `구좌 상품`(상시 할인, 노출만) · `하루특가 편성` · `후보 상품`. 상품 역할 구분은 `plans/05_기능연결_점검표.md` 4.6 (R18)
