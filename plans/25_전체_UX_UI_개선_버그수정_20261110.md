## 2. 항목별 변경 내용과 이유

### 1. 레퍼런스 라이브러리

**1-1 상세 겹침**
- **원인:** 이미지에 준 `max-height:100%`가 높이가 정해지지 않은 격자 칸에서는 먹지 않는다. 그래서 세로로 긴 이미지가 틀 밖으로 나와 글을 덮었다.
- **카드:** 비율을 고정한 틀 안에 이미지를 `object-fit: contain`으로 맞춘다.
- **상세 서랍:** 이미지를 원래 비율로 두되, 서랍 폭과 화면 높이의 60%를 넘지 않게 한다. 서랍 칸은 `grid-auto-rows: max-content`로 두어, 높이가 모자라면 칸을 줄이지 않고 스크롤한다.
- **확인:** 세로 9:24 예시에서 이미지 아래 끝(710)이 설명 시작(735)보다 위에 있다. 390px 화면에서도 겹치지 않는다.

**1-2 Pinterest**
- **가능 범위를 먼저 확인했다.** 공식 API는 앱 심사와 OAuth가 필요하다. 대신 공개 보드의 RSS(`보드주소.rss`)는 로그인 없이 읽힌다. 이 PC에서 실제로 핀 25개를 받았다.
- **구현:**
  - [Pinterest 보드] 탭 추가 (Pinterest 표시 포함)
  - 보드 주소 넣기 → 핀 목록 → [라이브러리에 담기]. 담은 핀은 [느낌] 탭에 모인다.
  - 보드 빼기
- **보드 주소 오류 안내:** 잘못된 주소, 핀 하나 주소, 검색 주소는 그 자리에서 문구로 알려 준다.
- **정리한 것:** 동작하지 않던 「핀터레스트 보드 연결 (연결 예정)」 버튼을 없앴다. 예시 데이터의 '핀터레스트 보드' 출처 표기는 '외부 사례'로 바꿨다. 실제 연동처럼 보이지 않게 하기 위해서다.

**1-3 직접 입력**
- 추가·고치기 창의 네 칸에 「직접 입력…」을 넣었다: 종류, 명분·시즌, 분류, 참고할 것.
- 서버에 저장된다 (`planner/data/references/refs.json`).
- 직접 입력한 값이 쓰이는 곳:
  - 직접 입력한 종류는 자기 탭이 생긴다 (예: '숏폼 영상').
  - 필터 선택지는 고정 목록이 아니라 실제 데이터에서 만든다.
  - 상세, 검색, 구좌 편집의 느낌 레퍼런스 목록, 브리프에서 그대로 보인다.

**1-4 즐겨찾기만**
- 체크박스 「★ 저장한 것만」을 별 아이콘이 붙은 토글 칩 「즐겨찾기만」으로 바꿨다. 즐겨찾기 개수도 보여 준다.
- 즐겨찾기는 서버에 저장한다.
- 용어를 구좌 편집과 같게 맞췄다: 카드·상세 버튼은 「☆ 즐겨찾기 / ★ 즐겨찾기 해제」, 아이콘만 있는 버튼의 읽기 이름도 같다.

### 2. 타임라인·캘린더 (홈)

- **2-1 이름 잘림:** 짧은 막대는 마우스를 올리거나 포커스·누르면 이름이 펼쳐진다. 줄임표만 남기지 않는다.
- **2-2 명분 노드:**
  - 가까운 명분끼리는 층을 나눠 배치한다 (겹침 방지).
  - 층마다 줄기선 길이를 다르게 해 어느 날짜의 명분인지 이어 보이게 했다.
  - 누르는 자리는 최소 32px이다.
- **2-3 기간 이동:**
  - 버튼은 화살표 아이콘과 「이전 4주 / 다음 4주」 글자로 바꿨다. 캘린더에서는 「이전 달 / 다음 달」이다.
  - 예전에 '-'로 보이던 진짜 원인은 아이콘 클래스 이름 `lead`가 홈의 `.lead{height:2px}`(준비 기간 선)와 겹친 것이다. 클래스 이름을 바꿔 고쳤다.
  - 단위를 서로 다르게 둔 이유: 타임라인은 '오늘부터 4주' 흐름을 보는 화면이고 캘린더는 달력 한 장 단위로 보는 화면이다. 그래서 단위를 하나로 억지로 맞추지 않고, 버튼 글자로 단위를 드러냈다.
- **2-4 빈 기간 문구:** 「11일 비어요」를 「11일간 빈 기간」으로 바꿨다. 범례도 「빈 기간 (걸린 페이지 없음)」이다.
- **2-5 기간 고르기:**
  - 끌기를 없애고 「시작일 클릭 → 끝나는 날 클릭」으로 바꿨다.
  - 고르는 중에는 점선, 확정되면 실선으로 구분한다. 고르는 동안 안내 문구가 바뀐다.
  - Esc를 누르거나 창을 닫으면 고른 것이 풀린다.
- **2-6 빈 기간 추천 문구:**
  - 「2주 제한」을 확인해 보니 비즈니스 규칙이 아니라 기본 제안값이었다 (plans/20 §4-1).
  - 빈 기간이 14일 이하면 전체를 넣는다. 넘으면 2주를 넣고, 이유와 함께 「빈 기간 전체로 바꾸기」 링크를 준다.
  - 겹침 안내 문구: 「몰에 걸린 다른 페이지와 기간이 겹쳐도 만들 수 있어요.」

### 3. 마인드맵·키워드 (브리프)

- **3-1·3-3 클릭 동작:**
  - 키워드를 누르면 펼치고, 다시 누르면 접는다. '더 펼치기' 버튼은 없앴다.
  - 접힘 상태는 '+가지 수', 펼침 상태는 접기 표시로 보여 준다.
  - 키보드 동작은 보조로 남겼다 (Enter, Space, ←/→).
  - **오늘 추가로 고친 버그:** 막 펼친 키워드를 '접힘'으로 계산하고 있었다. 그래서 다시 눌러도 접히지 않았다. 이제 펼치면 11개에서 17개, 다시 누르면 11개로 돌아간다.
- **3-2 복수 선택:**
  - 고르기는 키워드 왼쪽의 동그라미 체크로 따로 뺐다 (펼치기와 섞이지 않게).
  - 고른 칸에 「n개 · 여러 개 고를 수 있어요」를 표시하고, ✕로 뺀다.
- **3-4 설정 버튼:** 큰 「설정에서 보기」 버튼을 작은 링크 「연결 설정 보기」로 바꿨다.

### 4. 브리프

- **4-1 메인 카피 이름표 깨짐:** 원인은 이름표 줄 높이 44px이었다. 이름표를 「(선택)」으로 줄이고, 안내는 입력칸 placeholder로 옮겼다.
- **4-2 용어:**
  - 「규칙으로 만든 문장」 → 「키워드로 만든 카피 틀」
  - AI 버튼은 「AI 제안 · 준비 중」으로 비활성 처리했다 (동작하는 척하지 않음).
- **4-3 상품 연동:** 홈 [새 기획안] 시작 창(브랜드기획전, 런칭, 클리어런스)에서 상품을 검색해 최대 10개 고른다. 고른 상품은 기획안의 상품 풀에 연결된다. 직접 입력(출발점 글)도 함께 남겼다.
- **4-4 레퍼런스 상세 (오늘):**
  - 느낌 레퍼런스 카드마다 [자세히]를 두었다. 누르면 브리프 위에 옆 서랍(공통 `.v2drawer`)이 열린다.
  - 서랍에 나오는 것: 이미지, 출처, 종류, 분류, 시즌, 참고할 것, 메모, 링크. 서랍 안에서 고르기·빼기도 된다.
  - Esc를 누르거나 바깥을 누르면 닫히고, 포커스는 그 카드로 돌아간다.
  - 목록은 라이브러리에 저장된 것을 앞에 두고(즐겨찾기 먼저), 그다음 예시를 보여 준다.
  - [라이브러리에서 더 보기]는 새 탭으로 라이브러리 [느낌] 탭을 연다. 원래는 '예시예요' 알림만 떴다.
- **4-5 '참고할 점이 글씨':** 이름표 「참고할 점」과 칩 「글씨」가 이어 읽힌 것이었다. 「참고할 것 (여러 개)」와 「글씨체」로 바꿨고, 예전에 저장한 '글씨'는 불러올 때 '글씨체'로 옮긴다.

### 5. 구좌 편집

- **5-1 뒤로가기와 저장:**
  - 단계 막대에 「← 이전: 구좌 구성」을 두었다.
  - 화면을 떠날 때 저장 대기 중인 값은 `keepalive` 요청으로 마저 저장한다. 크기가 너무 크면 떠나기 전에 확인을 묻는다.
- **5-2 '더 찾기':** 이제 다른 레퍼런스를 그 자리에서 펼친다. 하나도 없으면 빈 상태 문구와 라이브러리 링크를 보여 준다.
- **5-3 상품 섞임:**
  - **원인:** 카드 ID 겹침. 예시 데이터의 c1~cN 번호와 저장된 카드 번호가 같았다.
  - ID는 소금 값을 섞어 만들고, 불러올 때 겹치는 ID는 새로 붙인다.
- **5-4 여러 카드 동시 편집:** 카드 문구를 여러 장 동시에 펼칠 수 있다. 입력 상태는 카드마다 따로 유지된다. 「모두 펼치기 / 모두 접기」도 넣었다.
- **5-5 구좌 추가:**
  - 구좌 목록 아래에 「+ 구좌 추가」를 두었다. 선택한 구좌 바로 아래에 들어간다 (중간에 넣기 가능).
  - 구좌 종류를 고르는 창이 뜬다.
  - 구좌가 없을 때는 빈 상태에서 [첫 구좌 추가]로 시작한다.
- **5-6 자유형:** 완전한 자유형 에디터 대신 지금 구조에서 최소한으로 확장했다.
  - 빈 기획안으로 시작할 수 있다 (구좌 구성의 '빈 구성' 선택 또는 구좌 0개).
  - 아무 위치에 구좌 추가, 복제, 삭제, 종류 바꾸기, 끌어 옮기기가 된다.
- **5-7 삭제 안전장치:**
  - 구좌 삭제처럼 중요한 삭제는 확인창을 띄우고 영향을 알려 준다. 예: 「이 구좌에 넣은 것(상품 n개·문구…)도 함께 지워져요」, 할인 행은 남는다는 안내.
  - 카드 삭제처럼 가벼운 삭제는 확인 없이 지우고, 6초 동안 [되돌리기]를 준다.

### 6. 와이어프레임 에디터

- **6-1 편집 패널 (일부):**
  - 패널 머리를 「제목 + 복제·삭제」, 「n번째 구좌 · 종류」, 「종류 바꾸기」로 묶었다.
  - 버튼 위계를 정리했다: 위험한 동작은 고스트 빨강, 주 동작은 초록.
- **6-2 뒤로가기와 실행 취소:**
  - 화면 이동(「← 이전」)과 편집 이력(머리 줄의 실행 취소·다시 실행)을 분리했다.
  - 단축키: Ctrl+Z, Ctrl+Shift+Z, Ctrl+Y. 입력칸 안에서는 브라우저 기본 동작을 따른다.
- **6-3 구좌 선택 이동:** 목록에서 구좌를 누르면 그 구좌로 스크롤하고 강조한다. 고정 머리 높이를 CSS 변수(`--v2-head-h`)로 재서 가려지지 않게 했다.
- **6-4 반응형 (오늘):**
  - **원인 1 (편집 화면):** 980px 이하에서 패널을 '겹쳐 여는 창'으로 바꾸는 규칙이 있었는데, 파일 뒤쪽의 `.panel{position:sticky}`가 그 규칙을 덮어썼다. 그래서 좁은 화면에서 패널이 화면 밖으로 밀렸다. sticky를 981px 이상에만 걸었다.
  - **원인 2 (라이브러리, 홈 기획안 목록):** 카드의 격자 열이 내용 폭(긴 탭 줄)만큼 늘어났다. 열을 `minmax(0,1fr)`로 묶었다.
  - **원인 3 (모든 화면 머리 줄):** 폰 폭에서 줄이 넘쳤다. 480px 이하에서는 로고 글자, '예전 화면' 링크, 출처 글자를 숨기고 점만 남긴다 (읽기 이름은 유지). 미리보기·구좌 구성·편집 머리 줄에 실수로 두 번 들어갔던 이전/다음 버튼도 지웠다.
  - **확인:** 8개 화면 모두 390px에서 문서 폭 390 (가로 스크롤 없음). 900px에서 편집 패널이 오른쪽 440px 창으로 열린다. 1440px에서는 따라붙는(sticky) 동작이 그대로다.

### 7. 미리보기·내보내기

- **7-1 '주의' 문구:**
  - '주의'를 구체적인 이름과 이유 한 줄로 바꿨다. 이름은 기간 겹침, 원가율, 할인 폭, 상품 확인, 판매 중지, 유의사항, 알약 문구.
  - 단순 참고는 「참고」로 낮추고 경고처럼 보이지 않게 했다.
  - 제목은 「확인하면 좋은 것 (고치지 않아도 내보낼 수 있어요)」.
- **7-2 내보내기 위치:**
  - 내보내기 카드를 위로 올렸다. 단계 막대에 고정된 [내보내기] 버튼도 넣었다.
  - 무엇이 어떤 파일로 나가는지 한 줄씩 안내한다 (ZIP, html, csv).

## 5. 못 했거나 더 검토할 것

- **6-1 '디자인 툴 같은' 패널 (일부만 함):** 머리와 버튼 위계까지만 정리했다. 탭 안 입력 묶음(문구, 모양, 상품)을 디자인 툴처럼 속성 패널로 다시 짜는 일은 별도 설계가 필요하다. 와이어프레임 위에서 바로 고치는 방식(직접 조작)도 함께 검토하는 것이 좋다.
- **브리프 느낌 레퍼런스 선택 (아직 저장 안 함):** 고른 것과 참고할 것이 기획안에 저장되지 않는다 (예전부터 그랬음). 구좌 편집의 느낌 레퍼런스는 저장된다. 브리프 값을 저장하려면 V2Meta에 칸을 하나 더하면 된다.
- **라이브러리 → 기획안 직접 담기 (가짜 버튼 없앰):** 예전의 「기획안에 담기」는 저장 없이 알림만 띄웠다. 그래서 없애고, 「구좌 편집 › 레퍼런스 탭에서 붙여요」로 안내를 바꿨다. 라이브러리에서 기획안을 골라 바로 담으려면, 다른 화면에서 기획안 파일을 고치는 흐름이 필요하다. 동시 편집 충돌도 검토해야 한다.
- **예시 데이터로 남은 것:** 라이브러리의 '예시' 카드(자사몰 지난 페이지 캡처), 구좌 레퍼런스(REFS)의 레이아웃 가져오기, AI 문구·후기 요약. 모두 화면에 '예시'·'준비 중'으로 표시되어 있다.
- **사내망에서 Pinterest:** 이 PC에서는 RSS와 이미지가 모두 받아졌다. 다른 사내 PC나 망에서 막히면 보드 칸에 「핀터레스트에 연결하지 못했어요. 사내망에서 막혔을 수 있어요」가 뜬다. 다른 기능은 영향이 없다.

## 6. 제약과 향후 고려

- **Pinterest RSS는 비공식 기능이다.** 보드마다 최근 핀 25개 안팎만 오고, Pinterest가 형식을 바꾸거나 막으면 멈춘다. 오래 쓸 기능이면 공식 API(앱 등록, OAuth, 심사)로 옮기는 것을 검토해야 한다. 그때도 저장 형식(`pin_id`, `pin_img`, `board`)은 그대로 쓸 수 있다.
- **핀 이미지는 저장하지 않는다.** 볼 때마다 받아 온다 (서버 메모리 캐시 200장). 저작권 부담은 줄지만, 핀이 지워지면 담아 둔 레퍼런스 이미지도 비게 된다.
- **직접 올린 이미지는 이 PC의 프로그램 폴더에 저장된다.** 여러 사람이 같은 라이브러리를 쓰려면 공유 저장소(사내 파일 서버나 DB)가 필요하다.
- **AI 기능은 연결 전이다.** 버튼은 비활성 「준비 중」으로 표시했다.
