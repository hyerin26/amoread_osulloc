# 21 핀터레스트 가져오기 — 구현 계획 (초안, 2026-11-07)

관련: plans/20 §4-9-1(느낌 레퍼런스), §4-12(레퍼런스 라이브러리, 목업 28)

## 0. 목표 [사용자]
- 멘토님이 보시는 핀터레스트 보드를 AMOREAD 레퍼런스 라이브러리로 가져온다.
- **핀터레스트에서 검색하는 것과 다른 쓸모**가 있어야 한다.

## 1. 확인한 사실과 한계 [사실 — 공식 문서로 다시 확인 필요]
- 공식 API(v5)로 보드의 핀 목록을 읽는다 (`GET /v5/boards/{board_id}/pins`). 승인된 앱, 로그인 토큰(OAuth), `boards:read`·`pins:read` 권한이 필요하다.
- 읽을 수 있는 보드는 **로그인한 계정의 보드**와 **그 계정이 초대된 그룹 보드**뿐으로 보인다 (외부 예제 기준).
  - 남의 공개 보드를 아무거나 긁어 오는 건 API로 안 되고, 크롤링은 이용약관 위반 소지가 있다 → 하지 않는다.
- 앱 권한은 Trial → Standard 두 단계이고, 심사가 필요하다.
- 저장 규칙(개발자 정책): API로 받은 정보는 원칙적으로 저장하지 않는다.
  - 커뮤니티 답변 기준으로 **핀·보드 ID는 참조로 보관해도 대체로 괜찮고, 이미지와 개인정보는 보관하지 않는다**.
  - → AMOREAD에는 **핀 ID + 우리가 붙인 태그·메모만** 저장한다. 이미지는 볼 때마다 핀터레스트에서 받아 보여준다.

**[가설] 그래서 현실적인 길:** 멘토님 **본인 계정의 보드**를 연결한다. 남의 공개 보드에서 좋은 핀은 멘토님 보드에 저장(핀 저장)하면 따라 들어온다.

## 2. 핀터레스트 검색과 다른 점 — 기능 제안 [제안]
담당자가 손으로 적는 칸이 늘면 일이 된다 → **AMOREAD가 먼저 채우고 담당자는 확인만** 하는 쪽으로.

| # | 기능 | 핀터레스트에선 | AMOREAD에선 |
|---|---|---|---|
| 1 | **받은 핀 정리함** | 보드에 계속 쌓이기만 함 | 새로 들어온 핀이 '받은 것'에 모임 → 쓸 것만 남기고 [넘기기]. 라이브러리가 쓰레기통이 되지 않음 |
| 2 | **우리 업무 말로 자동 태그** | 이미지·영문 키워드 검색 | 핀 제목·설명·보드 이름을 명분 사전(시즌·절기·행사)·분류 5종·혜택 방식 사전과 맞춰 **태그 제안**. 담당자는 칩 눌러 확인만 |
| 3 | **기획안 맥락으로 미리 거름** | 매번 검색어를 새로 침 | 브리프의 명분·고른 키워드·분류로 걸러서 '이 기획안에 맞을 핀'을 먼저 보여줌 (브리프·구좌 편집의 느낌 레퍼런스 고르기) |
| 4 | **왜 이 이미지인지 남김** | 저장만 됨 | 참고 포인트(색감·구도·소품·글씨·카피 톤) + 한 줄 메모 → **디자이너 전달에 같이 감** |
| 5 | **긴 페이지 캡처를 구좌로 쪼개기** | 한 장짜리 이미지 | 프로모션 페이지 통째 캡처 핀이면 영역을 그어 **구좌 사례**로 등록 (잘라 저장하지 않고 좌표만 저장) → 구조 레퍼런스로도 씀 |
| 6 | **우리 실제 페이지와 나란히** | 없음 | 같은 명분에 자사몰이 실제로 걸었던 페이지를 옆에 보여줌 → "우리 톤에 맞나" 판단 |
| 7 | **쌓여서 다시 떠오름** | 없음 | 기획안에 쓴 핀은 '지난 기획안에서 n번 씀', 다음 해 같은 명분 때 다시 추천 |

[제안] 먼저 만들 것: **1·2·4**(가져온 핀을 쓸 수 있게 만드는 최소) → 다음 **3·7**(이미 있는 브리프·담기 흐름에 연결) → 마지막 **5·6**(손이 많이 감).

## 3. 단계별 구현 [제안]
### 0단계 — API 없이 (지금 바로, 프론트만)
- 목업 28의 [＋ 레퍼런스 추가]에서 **핀 링크 붙여넣기**를 받는다. `pinterest.com/pin/숫자` 모양이면 핀 ID를 뽑아 '핀터레스트' 출처로 표시한다.
  - `pin.it` 짧은 주소는 원래 주소를 찾으려면 서버가 필요 → 엔지니어 검증.
- 이미지는 담당자가 캡처한 파일을 같이 넣는다 (담당자 본인 파일).
- 2번 자동 태그, 4번 참고 포인트는 이 단계에서도 동작한다 (사전 맞추기는 브라우저 안에서, 외부 전송 없음).

### 1단계 — 보드 연결 (엔지니어: 앱 심사·서버)
- ⚙ 설정·데이터 › 외부 연결 › [핀터레스트 연결] → 핀터레스트 로그인·권한 허용 → **가져올 보드 고르기**(체크).
- 서버가 고른 보드의 핀 목록을 주기적으로 읽어 **핀 ID만** 받은 핀 정리함에 넣는다.
- 라이브러리에서 이미지는 볼 때 받아 온다. 연결이 끊기거나 원본 핀이 지워지면 '원본 없음'으로 표시한다(태그·메모는 남김).

### 2단계 — 차별 기능 연결 (프론트 중심)
- 받은 핀 정리함 탭(또는 라이브러리 위 알림 줄 '새 핀 n개'), 태그 제안 확인 UI.
- 브리프·구좌 편집의 '느낌 레퍼런스 고르기'에 맥락 필터를 연결하고, 기획안에 담으면 사용 횟수를 올린다.
- 디자이너 전달(미리보기·내보내기)에는 **핀 링크 + 참고 포인트 + 메모**를 넣는다. 이미지를 파일 안에 넣어도 되는지는 정책 확인 뒤에.

### 3단계 — 선택
- 구좌로 쪼개기(영역 긋기 UI), 자사몰 페이지 나란히 보기.
- AI로 이미지 보고 태그 제안 → 외부 AI로 이미지를 보내는 일이라 보안 검토 대상. 지금은 하지 않음.

## 4. 저장하는 것 / 안 하는 것 [제안]
- 저장: 핀 ID, 보드 ID, 핀 링크, **우리 태그·참고 포인트·메모·구좌 영역 좌표·사용 횟수**
- 저장 안 함: 핀 이미지 파일, 핀 작성자 정보, 핀터레스트 계정 개인정보
- 핀터레스트로 보내는 것: 로그인 토큰뿐. **사내 데이터(상품·원가·매출·기획안)는 보내지 않는다.**

## 5. 엔지니어 검증 요청 (→ plans/16에 옮길 것)
- 핀터레스트 개발자 앱 등록·심사(Trial/Standard), 회사 명의로 할지
- 사내망에서 `api.pinterest.com` 호출이 되는지, 보안성 검토 대상인지
- 토큰 보관: 서버에 암호화 저장, 브라우저에 두지 않음, 만료·갱신 처리 (보안 개발 가이드 v3.3)
- 정책: 핀 ID·링크·우리 태그 보관 허용 범위, 화면에 이미지 띄우는 방식, 디자이너 전달 파일에 이미지 넣기 가능 여부 — 핀터레스트 개발자 지원에 확인
- 외부 이미지 저작권: 내부 참고용으로만 쓴다는 원칙을 화면에 표시할지
- 동기화 주기, 호출 한도, `pin.it` 짧은 주소 풀기

## 6. 정할 것 (사용자·멘토님)
- **멘토님이 핀터레스트를 어떻게 쓰시는지**: 본인 계정 보드에 저장해 두시는지, 남의 공개 보드를 그때그때 보시는지 → 1단계가 쓸모 있는지가 여기서 갈림
- 제안 기능 1~7 중 먼저 만들 것
- 받은 핀 정리함을 라이브러리의 탭으로 둘지, 알림 줄로 둘지
