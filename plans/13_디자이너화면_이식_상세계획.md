## 5. 화면별 이식 계획 (3장 A안, 4장 A안 기준)

공통: 각 화면은 새 파일 하나에 둔다(`js/am/` 아래). 데이터 저장 형식은 6장의 추가만 한다. 화면을 하나 마칠 때마다 사용자 수동 확인을 받는다.

### R1. 앱 막대와 단계 (S00 연결, 앱 막대)
- 파일: `index.html`(상단 구조), `app.js`(화면 전환), `hub.js`(STEPS, 단계 이동), `am.css`
- 단계: `brief`, `direction`, `products`, `editor`, `preview` + `library`. 예전 단계 ID(`promo`, `page`, `deliver`)는 다른 파일이 보내는 이벤트(`am:open-step`, `am:go-step`)를 위해 새 ID로 바꿔 받는 표를 둔다
- 앱 막대: 디자이너 모양 그대로(로고, 묶음 탭, 저장, 실행 취소, 주 버튼). 주 버튼 문구는 화면마다(브리프 '기획 방향으로', 기획 방향 '상품·혜택으로', 상품·혜택 '구좌 편집으로', 구좌 편집 '기획안 미리보기', 미리보기 '편집 화면으로')
- 홈: D1을 디자이너 모양에 더 맞춤. 다시 열면 마지막 단계로(기획안별로 이 브라우저에 기억)
- 다음에 할 일: 앱 막대 아래 접히는 띠(개수 + 펼치면 목록)로. 옆 패널은 단계별 근거만
- 완료 기준: 맨 위가 디자이너 스크린샷과 같은 구성, 모든 단계 이동·떠나기 확인·담기 알림의 [보기]가 새 단계로 감

### R2. 01 브리프 (S03)
- 파일: `brief.js`
- 왼쪽 카드: 프로모션명(=기획안 제목), 진행 기간, 주요 목적(칩), 타깃 상황(타깃·고객 상황) / 오른쪽 카드: 지금 기획하는 이유(=명분), 기획 콘셉트(=컨셉) + 안내
- 디자이너에 없는 우리 것: 페이지 유형, 목표, 배경, 운영 조건, 할인 외 혜택 → 왼쪽 아래 '더 적기' 카드. 명분 근거·컨셉 이력·캘린더 반영 → 옆 패널 그대로
- 완료 기준: 디자이너 브리프와 같은 2열, 기존 필드 모두 저장

### R3. 02 기획 방향 (S04, 새 화면)
- 파일: 새 `direction.js`
- 왼쪽 카드 '기본 기획 방향': 기획하는 이유(명분), 프로모션 콘셉트(컨셉), **대표 카피**(6장 새 칸), [다른 카피 예시 보기]
- [다른 카피 예시 보기]: AI를 쓰지 않는 버전. 명분 사전 씨앗, 컨셉, 목적에서 문장을 만들어 돌려 보여줌. 안내 띠에 '미리 준비한 규칙으로 만든 예시예요. AI를 쓰지 않아요'를 디자이너처럼 밝힘. 멘토님 툴의 Claude 기획 기능은 실데이터 사용 승인(인터뷰 F4) 뒤 버튼 하나로 추가
- 오른쪽 카드 '제안 근거 확인': 우리 실데이터 근거(명분 D-day·준비 시작, 작년 같은 명분 행사, 같은 시기 잡힌 행사, 최근 컨셉 겹침) + '기획에 참고할 섹션'(레퍼런스 카드 2개, R7 이후)

- 완료 기준: 대표 카피 저장, 예시 돌려 보기, 구성안 만들기가 04에 반영
