# 23 새 버전(v2)을 앱에 붙이기 (2026-11-07)

[사용자] 업무 과정대로 화면을 다 만들었으니 새 버전을 앱에 붙이자. 예전 화면은 건드리지 않는다.

## 1. 어떻게 붙였나 [사실]
- 주소: **http://127.0.0.1:9751/v2/** (홈). 예전 화면은 `/` 그대로이고, 새 버전 윗줄의 [예전 화면]으로 오갈 수 있다.
- 화면 8개: `home`, `brief`, `compose`, `editor`, `preview`, `deals`, `library`, `settings`. 비교(26)·검색창(27) 목업은 디자인 참고라 넣지 않았다.
- 앱 보안 머리(CSP `script-src 'self'; style-src 'self'`) 때문에 목업 안의 `<style>`·`<script>`를 `static/v2/<화면>.css`·`.js` 파일로 나눴다. 토큰은 예전 화면과 같은 방식(`<meta name="planner-token">`)이다.
- 공통 틀(plans/20 §4-11):
  - 윗줄: 홈 · 레퍼런스 · ⚙, 예전 화면 링크
  - 기획안 막대: 01~04 단계, [상품·할인], [다음 →], [목록으로]
  - 파일: `static/v2/shell.css`·`shell.js`. 서버 호출은 `static/v2/api.js`
- 서버(`server.py`)에 더한 것은 두 가지:
  - `/v2/{화면}`: 정해진 이름만 열고, 나머지는 404
  - `GET /api/connections`: 키는 있음/없음만, 사용량은 `usage.summary()`
  - 예전 라우트와 파일은 그대로다.
- **이제 원본은 `static/v2`이다.** `plans/mockups`의 20~29는 디자인 기록으로 남긴다. 옮기는 데 쓴 스크립트는 한 번만 썼다.

## 2. 실제 데이터 / 아직 예시
| 화면 | 실제 | 아직 예시 |
|---|---|---|
| 홈 | [시작] → 고른 명분·씨앗을 브리프 중심 키워드로 넘김. [이어서 하기] → 브리프 | 일정표·이벤트·기획안 목록·명분 사전·실적 한 줄 |
| 브리프 | 근거 패널의 **검색**(네이버 검색어 트렌드: 오르는 중/줄어드는 중/꾸준, 가장 많이 찾는 달, 최근 4주 지수)과 **글**(네이버 뉴스·블로그, 관련 높은 순, 원문 새 탭). 중심 키워드에도 실제 근거. 연결 상태 한 줄 | 마인드맵 가지(검색광고 키가 오면 연관 키워드로), 우리 데이터, 메인 카피 제안, 느낌 레퍼런스 |
| 설정·데이터 | 외부 연결의 네이버 카드 3개 상태·오늘/이번 달 사용량, [연결 확인] 실제 호출('차', 검색 2·트렌드 1회) | 데이터 상태, 원가 파일, 사전과 목록 저장, 기획 기준 값 |
| 구좌 구성·구좌 편집·미리보기·상품·할인·레퍼런스 | - | 전부 예시 (목업 그대로) |

- 바깥으로 보내는 것은 키워드뿐이다. 브리프는 키워드를 **눌러 근거를 볼 때만** 부르고, 같은 키워드는 화면에서 한 번, 서버에서 6시간 캐시한다.

## 2-1. 기획안 하나로 잇기 (2026-11-07) [사실]
[사용자] 잇는 것부터 하자.
- **저장소는 예전 화면과 같은 것**(`planner/data/projects/{id}.json`, `/api/am/projects`)을 쓴다. 새 버전과 예전 화면이 같은 기획안을 본다.
- 새 버전만 쓰는 값은 `doc.v2`에 둔다: 분류 5종 `cls`, 출발 씨앗 `seed`, 고른 키워드 `keywords`, 마지막으로 연 단계 `stage`.
  - 예전 화면은 `v2`를 보내지 않으므로 **안 보내면 저장된 값을 그대로 둔다** (`store.save`). 예전 화면에서 저장해도 지워지지 않는다.
  - `amoread/api.py`의 `V2Meta`가 값 형식을 검사한다. 목록 요약에는 `cls`·`stage`가 더해진다.
- **홈**:
  - 기획안 목록·일정표의 내 기획안은 실제 목록이다. 예전 화면에서 만든 것도 '분류 미정'으로 보인다.
  - [시작]을 누르면 기획안을 **만들고** 브리프로 간다. 저장하는 것: 이름 '○○ 기획안', 명분·명분 날짜, 기간(정했으면), 분류, 씨앗.
  - [열기]·[이어서 하기]는 그 기획안의 마지막 단계로 간다.
  - 오늘 날짜는 실제 한국 날짜다. 몰 이벤트·명분·'지난 기획안 (예시)'는 아직 예시다.
- **기획안 막대**(`static/v2/plan.js`, 단계 화면 5개 공통):
  - 주소의 `?id=`로 기획안을 읽어 이름을 보여 준다. 단계·상품·할인 링크에 id를 붙이고, 연 단계를 `v2.stage`로 저장한다.
  - '저장 중… / 저장했어요 HH:MM / 저장 못 했어요'를 보여 준다. 고친 내용은 0.7초 모아서 차례로 저장하고, 응답이 그 사이 고친 내용을 덮지 않는다.
  - id가 없으면 '예시 기획안'으로 보이고 저장하지 않는다.
- **브리프**:
  - 기획안을 열면 저장된 명분(없으면 씨앗)이 중심 키워드가 된다.
  - 이름·고른 키워드·컨셉·누구에게(`brief.audience`)·메인 카피(`brief.key_copy`)·분류·기간·페이지를 채운다.
  - 고칠 때마다 저장한다. 키워드 고르기·빼기는 키보드로 해도 저장된다.
- **브리프 마인드맵 가지**(2026-11-07, [사용자] 키워드를 펼쳐도 가지가 안 생김):
  - 가지 = **검색광고 연관 키워드(키가 있으면 먼저 5개) + 그 말이 나온 뉴스·블로그 20건에서 여러 글(2건 이상)에 함께 나온 말**, 8개까지. `keywords.related_words`로 규칙으로 뽑으며 AI가 아니고, 호출도 늘지 않는다.
  - 키워드를 누르면 그 말의 가지가 생기고, 계속 펼쳐 갈 수 있다. 이미 펼쳐 둔 갈래는 바꾸지 않는다. '어디서 왔나요'는 글/검색으로 표시한다.
  - [한계] 기사 말이라 엉뚱한 말(인명·지명·기관)이 섞인다. 예: 피크닉 → 한강·노들섬·돗자리·그늘막 / 서울시장. 검색광고 키가 오면 나아진다.
- **[구좌 구성 추천 받기 →]**: 저장을 마친 뒤 같은 기획안의 구좌 구성으로 간다. 구좌 구성의 [이 구성으로 구좌 편집 →], 구좌 편집의 [다음]도 같다. 막대의 단계 링크도 기다리는 저장이 있으면 저장을 마친 뒤 이동한다 (`PLAN.flush`).
- **구좌 구성**(2026-11-07): 추천안을 고르면 그 구성이 기획안의 `page.sections`(구좌 이름·종류·넣은 이유·탭·진열 유형)와 `v2.compose`(고른 안)에 저장된다. 순서 바꾸기·이름 고치기·지우기·탭 묶기도 저장한다. 다시 열면 저장된 구성을 불러온다.
  - 구좌 편집에서 채운 내용은 같은 구좌(id)면 남는다. 지운 구좌의 내용은 사라진다.
  - [이 구성으로 구좌 편집 →]은 같은 기획안의 구좌 편집으로 간다.
- **구좌 편집**: 기획안의 구좌 목록을 읽고 고칠 때마다 저장한다.
  - 원래 칸에 넣는 것: 제목 → `headline`(앞 40자는 `name`), 설명 → `subhead`, 버튼 문구 → `cta`, 엑셀 카테고리명 → `zone_tag`(탭은 탭마다), 디자인 요청 → `designNotes`
  - 구좌의 `v2`에 넣는 것: 담는 것, 번호, 버튼 켜기·어디로, 추가 문구, 레퍼런스, 느낌 레퍼런스와 참고 포인트, 카드 모양, 후기, 이벤트 조건
  - 서버는 구좌 `v2` 하나를 20,000자까지만 받는다. 예전 화면이 구좌를 저장해도 같은 sectionId의 `v2`는 이어 붙인다.
  - 구좌 구성을 아직 안 정한 기획안이면 예시를 보여 주고 저장하지 않는다.
  - [한계] **카드에 넣은 상품은 아직 저장하지 않는다**(상품이 예시 P101…). 상품·할인을 실제 상품과 이을 때 같이 한다. 후기 고르기도 예시 후기 목록에서 고른다.
- **상품·할인** (2026-11-07): 기획안을 열면 실제 상품(`/api/products`, 491개)으로 바뀐다.
  - 정가·원가·평소 판매·쉰 기간·마지막 행사·이미 잡힌 행사(upcoming·running)는 실제 값이다. 판정·원가율·기준 안 최대는 화면 계산 그대로(원가율 45%).
  - **[+ 상품 찾아 담기]**: 이름 일부나 SEQ로 찾는다. 판매 중인 상품 먼저, 최근 28일 매출순, 30개까지. [할인 상품에](기준 안 최대와 20% 중 낮은 쪽)·[후보로]. 창을 닫지 않고 이어서 담는다.
  - 저장: 할인 상품 → `promo_rows`(상시, 할인 없음 = `큐레이션`, 조합 = `items`), 하루특가 → `promo_rows` 하루특가 행, 후보 → `pool`, 하루특가 후보·자리 수 → `deal_plan`. 화면에 못 그리는 행(모르는 SEQ)과 행의 다른 칸(promo·memo·category_tag)은 그대로 돌려놓는다.
  - 원가가 없는 상품(73개)은 판정 대신 '원가 없음'. 묶음 후보는 원가 있고 판매 중인 상품만.
  - [한계] 할인 깊이별 반응·예상 매출·리뷰·지난 행사 할인 기준은 아직 예시(화면에 '예시' 표시). 상세의 지난 행사는 마지막 1건만. 추가 혜택은 저장 안 함. 하루특가 날짜는 기획안 기간 전체(31일까지).
- **미리보기**: 막대만 이어졌고 화면 안은 아직 예시다.
- [한계] 같은 기획안을 두 창에서 동시에 고치면 나중에 저장한 쪽이 남는다.

## 4. 점검한 것
- 8개 화면 200. CSP 머리 있음. 화면이 부르는 css·js가 모두 열림. 화면 사이 링크는 `/v2/` 안에서만. 이상한 주소(`/v2/index`, `/v2/home.html` 등)는 404.
- `/api/connections`: 토큰 없으면 401. 응답에 `.env`의 키 값이 들어 있지 않음.
- 브리프 실데이터 표시 함수(오르는 중·가장 많이 찾는 달·링크 새 탭·이스케이프·키 없음/한도 문구·같은 키워드 한 번만 부르기) 단위 점검.
- 화면 모양은 사람이 직접 본다 (자동 브라우저 시험은 하지 않음).
