# 신규 구좌편집기 UX 재배치 — 요소별 근거 (2026-11-15)

- **대상:** `/v2/editor-next` (기존 구좌 편집 → [신규 편집기로 열기 (시험)])
- **원칙:**
  - 기능·저장 형식은 그대로 (구좌 추가·삭제·복제·순서, 유형 변경, 요소 추가, 상품·후기·레퍼런스 연결, 검수, 실행 취소, JSON·HTML 내보내기)
  - 바꾼 것은 위치·크기·간격·문구·보이는 때뿐이에요
- **참고:**
  - Figma UI3 — 왼쪽 레이어, 가운데 캔버스, 오른쪽 속성. 패널은 1px 선으로 나뉘고, 오른쪽 위 탭이 1단 탐색
  - Relume 와이어프레임 — 구좌 목록 행에 마우스를 올리면 행 동작이 뜨고, 캔버스 위에 페이지 도구
  - 앱의 Green UI v2.5.1 토큰. 새 색·크기 값은 만들지 않았어요
- **스킬:** impeccable(작업 화면 = Operate 모드, craft floor), ui-ux-pro-max 점검 항목

---

## 0. 사용자와 목표

**누가:** 오설록몰 프로모션 기획자. 사무실 노트북(1280~1920)에서 기획안 하나를 30분~1시간 다듬어요.

**이 화면에서 하는 일 (빈도순):**
1. 구좌를 하나씩 골라 문구 쓰기 → 상품 연결 → 다음 구좌
2. 구좌 순서 바꾸기·추가·복제·삭제
3. 빠진 것 확인(검수) → 그 구좌로 가서 고치기
4. 디자이너에게 넘길 파일 내보내기

**성공:** 6~10개 구좌를 고치는 동안 화면을 옮기거나 스크롤로 도구를 찾지 않고, 지금 무엇을 고치는지 늘 알아요.

## 7. 확인

- **기능** (브라우저에서 직접): 구좌 추가 → 삭제 → 순서 바꾸기 → 실행 취소, 내보내기 메뉴(고르면 닫힘), 검수 창 → 구좌 이동, 요소 추가·선택, 유형 변경 창. 결과가 전과 같음
- **오류:** 신규 편집기(실제·예시)·기존 편집기·브리프 콘솔 오류 없음
- **e2e** (`tests/e2e/test_editor_next.py`): 내보내기가 메뉴 안으로 들어가서 3번 테스트의 모양 확인 3줄을 새 구조에 맞춤 (검수 버튼 36px, 메뉴 안 내보내기 2개, 밑줄 탭, 1px 선, 세 칸 첫 줄 높이 같음). 이 PC엔 Playwright가 없어 같은 값을 브라우저에서 확인

## 9. 2차 — 왼쪽·오른쪽 나누는 기준 (같은 날, 사용자 피드백)

**피드백:**
- 왼쪽 탭(구성·추가·자료)이 왜 필요한가
- 구좌 추가가 구성과 추가 탭에 겹침
- 목록이 와이어프레임처럼 접히는 게 불편함
- 상품 연결·구좌 상세 편집은 오른쪽이 편했음

**기준:**

| 칸 | 다루는 것 | 고른 것에 따라 바뀌나 |
|---|---|---|
| 왼쪽 | 페이지 전체 — 어떤 구좌가 어떤 순서로, 구좌 추가 | 아니요 |
| 가운데 | 결과 보기·고르기 | — |
| 오른쪽 | 지금 고른 구좌(요소) 하나에 하는 일 전부 — 문구·상품·배치 편집, **요소 추가, 자료 연결** | 예 |

**결론:**
- 요소 추가와 자료(상품·후기·레퍼런스) 연결은 '고른 대상에 넣는 일'이라 오른쪽이 맞아요
- 왼쪽에서 고르고 오른쪽에서 결과를 확인하던 시선 왕복이 없어져요
- Figma는 넣을 것(Assets)을 왼쪽에 두지만, 이 앱의 기존 구좌 편집기가 상품 연결을 오른쪽에서 해 왔고 사용자도 그쪽이 편하다고 했어요

| 요소 | 전 | 지금 |
|---|---|---|
| 왼쪽 탭(구성·추가·자료) | 왼쪽 칸 맨 위 | 없앰. 왼쪽 첫 줄은 "페이지 구좌 ……… ＋ 구좌 추가" |
| 추가 탭의 '구좌 추가' | 구성 탭의 [＋ 구좌 추가]와 같은 일(같은 유형 선택 창) | 없앰 (목록 위 버튼 하나) |
| 추가 탭의 '요소 추가' | 왼쪽 | 오른쪽 제목 줄 [요소 추가] → 오른쪽 칸이 요소 목록으로 바뀜, 요소 목록부터 보임. [완료]로 편집 |
| 자료 탭 | 왼쪽 | 오른쪽 제목 줄 [자료 연결] → 같은 방식 |
| 구좌 접기·펼치기 화살표 | 구좌마다 | 없앰. 구좌 안에 넣은 요소는 늘 펼쳐 보임 (대부분 구좌는 요소가 없어 목록은 평평) |
| 보기 안의 제목 줄 | — | 지금 보기 버튼(그린) + [완료](주 버튼)만. 다른 보기 버튼은 숨겨 제목 자리 확보 |

**바꾼 코드:**
- `editor-next.html`: 보기 전환 버튼과 요소·자료 목록을 오른쪽 칸으로 옮김
- `app.js` 두 줄: 목록을 늘 펼침, 요소 추가 기본값을 '요소'로
- 자료 안내 문구 "‘추가 > 요소’를 사용하세요" → "[요소 추가]에서 넣어요"
- e2e: 요소 추가 전 '요소' 전환을 누르던 줄 삭제, 첫 줄 맞춤 확인 대상을 `.en-listhead`로

**확인:**
- 구좌 추가·삭제·순서·실행 취소
- 요소 추가(상품 카드 1개 들어감)
- 자료 연결 보기와 [완료]로 복귀
- 콘솔 오류 없음
- 1440·1024 가로 넘침 없음

## 10. 3차 — 요소 추가는 왼쪽 팔레트로 (같은 날, 사용자 피드백)

**피드백:** 요소 추가는 왼쪽에 있어도 될 것 같음

**판단:** 2차처럼 오른쪽에서 [요소 추가]를 누르면 오른쪽 칸이 요소 목록으로 바뀌어, 넣는 동안 속성이 가려졌어요(넣고 → [완료] → 고치기, 3단계). 넣을 것을 왼쪽에 늘 펼쳐 두면 왼쪽에서 끌어 놓거나 누르고 → 오른쪽에서 바로 고치기, 2단계로 줄어요. Figma(Assets)·Relume(왼쪽에서 끌어 캔버스로)와 같은 방향이에요.

**정리된 기준:**
- **왼쪽 = 넣을 것** (페이지 구좌 목록 + 구좌 추가 + 요소 팔레트)
- **가운데 = 결과**
- **오른쪽 = 고른 것 고치기** (문구·상품·배치 + 자료 연결)

자료 연결은 '고른 구좌·요소의 값'을 정하는 일이라 오른쪽에 그대로 둬요. 상품 고르기도 이미 오른쪽 내용 > 상품에 있어요.

| 요소 | 2차 | 3차 |
|---|---|---|
| 요소 추가 | 오른쪽 제목 줄 버튼 → 칸 전환 | 왼쪽 칸 아래 "넣을 요소" 팔레트. 늘 보임, 2열 타일 9개, 높이 최대 40%. 설명은 마우스를 올리면 |
| 미리보기 빈 놓을 자리 | 요소 추가 보기일 때만 | 고른 구좌에 늘 아주 옅게 (끌어올 때·올렸을 때 진하게) |
| 오른쪽 제목 줄 | [요소 추가] [자료 연결] | [자료 연결]만 |

**코드:**
- `app.js` 4곳: 앱이 `window.AM_EN_PALETTE`를 켜면 팔레트를 늘 그리고 빈 놓을 자리를 늘 보임. 편집기 단독 실행은 전과 같음
- `editor-next-host.js`: 위 값 켜기, 타일 설명 title
- e2e: 요소 추가 전 보기 전환 클릭 삭제

### 구좌 추가 버튼과 유형 선택 창
- **버튼 위치:** 목록 머리 오른쪽 = 목록이 길어 스크롤해도 늘 같은 자리. 추가는 목록 전체에 하는 일이라 목록 제목 옆 (Figma 레이어 패널 +)
- **선택 창:** v1.12 원래 방식. 22개 유형을 미리보기 그림으로 비교하려면 왼쪽 칸(264px)보다 넓은 자리가 필요해서 큰 창(대화상자)을 유지했어요. 새 구좌는 지금 고른 구좌 바로 아래에 들어가요

### 팀원 피드백 (2026-11-14 새벽): "오른쪽 하단 세부 항목 정하는 부분이 작아서 한눈에 안 들어옴, 안에서만 스크롤하지 말고 전체 페이지 스크롤로"

## 11. 4차 — 요소 넣기는 필요할 때 여는 패널 (사용자 피드백: "넣을 요소가 너무 꽉 낌")

### 3차(늘 보이는 팔레트)를 원칙에 비춰 본 문제

| 원칙 | 3차 | 결과 |
|---|---|---|
| 한 칸에는 주된 목록 하나 | 264px 칸에 구좌 목록 + 2열 타일을 세로로 쌓음 | 둘 다 좁아짐: 목록은 높이 60%, 타일은 120px 폭에 이름만 (설명은 숨김) |
| 가끔 하는 일은 필요할 때만 (점진적 공개) | 요소 넣기는 구좌 편집보다 드문 일인데 늘 40% 차지 | 자주 쓰는 목록이 손해 |
| 넣을 곳을 가리지 않기 | 고른 구좌에 빈 놓을 자리를 늘 표시 | 미리보기가 실제와 다르게 보임 |

### 4차: 목록 머리 [＋ 요소] → 왼쪽 칸 옆에 패널 한 칸

- **패널:** 288px. 한 줄에 요소 하나(아이콘 · 이름 · 설명), 56px 행
- **열리는 방식:**
  - 1280px 이상: 미리보기를 밀어내며 열려 폰 틀을 가리지 않음 (1440에서 미리보기 520px, 폰 340px)
  - 1280px 미만: 미리보기 위에 겹쳐 열림 (그림자로 구분)
- **머리:** "요소 넣기 · ‘○○’에 넣어요", × / Esc / [＋ 요소] 다시 누름으로 닫힘
- **빈 놓을 자리:** 패널이 열렸을 때만 고른 구좌에 생김 (v1.12 '추가' 보기 그대로)
- **오른쪽 칸:** 요소를 넣는 동안에도 그대로 보임 → 넣고 바로 속성 고치기
- **목록 머리:** "페이지 구좌 ……… ＋ 구좌 ＋ 요소". 두 '추가'가 한곳에

**참고:** Figma(왼쪽 Assets/Insert 패널), Relume(왼쪽에서 끌어 캔버스로). 3차의 `app.js` 팔레트 스위치(`AM_EN_PALETTE`)는 되돌려 원본과 같음

### 15-2. 문구 원칙
- 설명문은 '무엇을 하면 무엇이 되나'만. 내부 이름(스키마, 렌더링, 필드, v0.6, eventTab(), Lab, PROMO_WORK)은 쓰지 않는다.
- 끄거나 비워도 되는 것은 결과를 같이 말한다 (「버튼 없이 둬요. 언제든 다시 켤 수 있어요」).
- 개발이 따로 필요한 것은 숨기지 않고 한 줄로 (「퀴즈 결과 계산·공유·…은 실제 페이지에서 따로 개발해야 해요. 여기서는 화면만 미리 봐요」).
