# 22 키워드 소재 창구 — 조사, 검색어 묶음, API 키 받는 법 (2026-11-07)

관련: plans/20 §3(키워드 소재 후보), plans/21(핀터레스트), plans/16 §2.6(엔지니어 검증 K1~K7)

## 1. 검색어 묶음(미리 정해 둔 검색어) [사용자 → 제안]
[사용자] 미리 정해 둔 검색어가 있고 그 필터를 고르면 그 검색어들로 검색한 결과가 한곳에 모여 보이면 어떨까?

- **네이버 창구(검색광고·데이터랩·뉴스·블로그): 된다.**
  - 이미 있는 '트렌드 키워드 그룹'(`settings/트렌드키워드.csv`, 화면 ⚙에서 고침)을 그대로 **검색어 묶음**으로 쓴다. 새 설정을 만들지 않는다.
  - 예) 묶음 '설 선물' = 설 선물 · 명절 선물세트 · 설 선물 추천. 이 묶음을 고르면 세 검색어의 연관 키워드, 검색 추이, 최신 글이 합쳐져 한 화면에 나온다.
  - 쓰는 곳은 브리프 키워드 확장(씨앗 대신 묶음 고르기)과 레퍼런스 라이브러리의 필터.
- **핀터레스트: 검색 결과를 그대로 모아 오는 건 안 된다.**
  - [사실] 공식 API의 핀 검색은 **내 계정의 핀만** 찾는다.
  - 아무 핀이나 검색어로 찾는 '파트너 핀 검색'은 베타라 일부 앱에만 열려 있고, 검색어당 상위 10개뿐이다.
  - 검색 결과 화면을 긁어 오는 것은 약관 위반 소지가 있어서 하지 않는다.
  - [제안] 그래서 이렇게 한다:
    - (가) 구독한 공개 보드(plans/21 §7 A안)에서 들어온 핀을 **검색어 묶음으로 거른다**. 핀 제목·설명·보드 이름에 묶음의 검색어가 들어간 것만 보여준다.
    - (나) 묶음마다 [핀터레스트에서 이 검색어로 보기]를 두어 새 탭으로 바로 연다(가져오지는 않음). 마음에 드는 건 캡처해 붙여 넣는다(B안).
    - (다) 파트너 핀 검색 베타는 엔지니어가 신청해 보고, 열리면 묶음 검색어당 상위 10개를 받아 온다.

## 3. API 키 받는 법
### 3-1. NAVER API HUB (검색·검색어 트렌드, 쇼핑인사이트까지 한 키) — 2026-11-07 바뀜
[사실] 네이버 검색·데이터랩 API가 **네이버 클라우드의 NAVER API HUB**로 옮겨 갔다 (공식 이관 가이드). 예전 developers.naver.com 키는 HUB 주소에서 쓸 수 없다.
1. 네이버 클라우드 콘솔(ncloud.com) 로그인 → 메뉴 › 전체 서비스 › Application Services › **NAVER API HUB** › 신청하기
2. Subscription에서 서비스 이용 신청 → 약관 동의
3. Application › **Application 등록** → API에 **검색**, **검색어 트렌드**, (나중에) **쇼핑인사이트**를 고르고 → 이름 넣고 완료
4. Application 관리 › **인증 정보**에서 **Client ID**, **Client Secret**을 복사해 아래 .env의 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`에 적는다
5. 요금: 종량제인데 **지금은 한시 무료**, 유료로 바뀔 때 미리 공지한다고 함 → 콘솔에서 **이용 한도·초과 알림**을 켜 둔다

### 3-2. 네이버 검색광고 (연관 키워드·검색수)
1. searchad.naver.com → 검색광고 계정으로 로그인 (회사 광고계정을 쓸지 담당자 계정을 쓸지는 plans/16 K1)
2. **도구 › API 사용 관리** → 약관 동의 → 발급
3. 나오는 **액세스 라이선스**, **비밀키**, 그리고 **CUSTOMER_ID(광고계정 번호)** 를 아래 .env에 적는다
4. PC 시각이 몇 분 이상 틀리면 거절(403)되니 윈도우 시간 자동 맞춤을 켜 둔다

### 3-3. 어디에 넣나: `.env` 파일
- 위치: **`C:\Users\amore\.claude\amoread_redesign\workspace\amoread_app\.env`** (run_redesign.bat이 여는 사본. main 사본을 쓸 때는 `C:\Users\amore\.claude\amoread\workspace\amoread_app\.env`)
- 같은 폴더의 **`.env.example`을 복사해 이름을 `.env`로 바꾸고** `=` 뒤에 값을 붙여 넣는다. 저장한 뒤 서버를 다시 켜면 반영된다.
- 규칙 (보안 개발 가이드: 하드코딩 금지)
  - 키는 `.env`에만 둔다. 코드·문서·채팅·메신저·목업 공유 ZIP에 넣지 않는다.
  - `.env`는 git에서 빠져 있다(`.gitignore`). 커밋되지 않는다.
  - 키가 새어 나갔다고 생각되면 NAVER API HUB·검색광고에서 바로 재발급한다.
- 확인: 키가 없는 창구는 화면·응답에 '연결 안 됨(no_key)'으로 나온다. 키를 넣은 뒤에도 '오류'면 메시지를 보고, 키 값은 남에게 보내지 말고 엔지니어에게 화면만 보여 준다.

### 3-5. 호출 한도 — 콘솔 한도에 닿기 전에 이 PC가 먼저 멈춤 (2026-11-07)
[사실] 받은 NAVER API HUB Application의 콘솔 한도 (사용자 화면 기준):
| 묶음 | 콘솔 하루 | 콘솔 한 달 | **AMOREAD 자체 한도 (하루 / 한 달)** |
|---|---|---|---|
| 네이버 검색 (블로그·뉴스·카페 합산) | 20,000 | 600,000 | **10,000 / 300,000** |
| 검색어 트렌드 | 제한 없음 | 40,000 | **1,000 / 20,000** |
| 쇼핑인사이트 | 제한 없음 | 40,000 | 아직 안 부름 (붙일 때 같은 방식으로 1,000 / 20,000) |
| 네이버 검색광고 키워드 도구 | (호출 간격 제한) | - | **1,000 / 30,000** |
- 콘솔 한도의 **절반**에서 멈춘다. 검색어 트렌드는 콘솔에 하루 한도가 없어 예전 데이터랩 하루 한도(1,000)를 썼다.
- `planner/usage.py`가 요청을 **보내기 전에** 센다. 실패한 요청도 센다. 하루·한 달은 한국 시간 기준이고, 기록은 `data/api_usage.json`이다.
- 한도에 닿으면 그 창구만 '오류'가 되고 "오늘 자체 한도 n회를 다 써서 멈췄어요. 내일 0시에 다시 돼요"라고 알린다. 다른 창구는 그대로 동작한다.
- 기록 파일을 읽지 못하면 0부터 세지 않고 **멈춘다** (모르는 채로 더 부르지 않음).
- 한도 값은 `config.API_LIMITS`에만 있다. 일부러 `.env`로 올릴 수 없게 했다.
- 호출을 줄이는 장치도 그대로 있다: 같은 키워드는 6시간 캐시, 트렌드·스카우트 다시 받기는 10분 간격.
- [한계] 이 PC에서 보낸 것만 센다. 같은 키를 다른 PC나 서버에서도 쓰면 합쳐서 세지 못한다 → **콘솔의 '한도 및 알림'도 같은 값(검색 하루 10,000 / 월 300,000, 트렌드·쇼핑인사이트 월 20,000)으로 걸고 80% 알림을 켜 둔다** (마지막 방어선)
- [제안] 설정·데이터 화면에서 창구별로 '오늘 n / 한도, 이번 달 n / 한도'를 보여 준다

### 3-4. NAVER API HUB로 바뀐 것 (2026-11-07 코드 반영)
| | 예전 (네이버 개발자센터) | 지금 (NAVER API HUB) |
|---|---|---|
| 주소 | `https://openapi.naver.com` | `https://naverapihub.apigw.ntruss.com` |
| 키 헤더 | `X-Naver-Client-Id` / `X-Naver-Client-Secret` | `X-NCP-APIGW-API-KEY-ID` / `X-NCP-APIGW-API-KEY` |
| 뉴스·블로그 검색 | `/v1/search/news.json` | `/search/v1/news` (블로그 `/search/v1/blog`) |
| 검색어 트렌드 | `/v1/datalab/search` | `/search-trend/v1/search` (요청 본문·응답은 같음) |

- 요청 값(query·display·sort, startDate·keywordGroups 최대 5개)과 응답 모양(items, results[].data[period, ratio])은 그대로 → 코드는 주소·헤더만 바꿈 (`config.NAVER_API_BASE`, `config.naver_headers()`)
- [사실·블로그 기준] 개발자센터 새 신청은 2026-07-31에 막혔고, 예전 방식은 2027-06-30에 끝남. 쇼핑·책·전문자료 '검색'은 HUB로 안 옮겨지고 끝남 (쇼핑인사이트는 HUB에 있음). 공식 문서로 다시 확인할 것
- HUB에 있는 것: 검색(뉴스·블로그·카페글·웹문서·이미지·지식iN·지역·백과·성인/오타 확인), 검색어 트렌드, 쇼핑인사이트(분야·기기·성별·연령·키워드별)

## 5. 창구가 여러 개일 때 키워드에 어떻게 보여 줄까 [제안 2026-11-07]
[결정·사용자] 핀터레스트는 붙이지 않는다. 붙일 창구는 **네이버(검색광고·데이터랩·뉴스·블로그 + 쇼핑인사이트·카페), 유튜브, 구글 트렌드**. 키를 받는 동안 다른 화면을 먼저 한다.

원칙: **창구(회사 이름)가 아니라 '무엇을 알려 주나'로 묶는다.** 담당자는 "네이버냐 구글이냐"보다 "많이 찾나, 오르나, 무슨 글·영상이 있나"가 궁금하다.

1. **마인드맵 가지는 한 목록으로 합친다**
   - 가지 후보: 검색광고 연관 키워드 + 구글 트렌드 관련 검색어 + 우리 데이터(명분 사전·지난 컨셉·리뷰 언급)
   - 같은 말은 띄어쓰기를 없애고 하나로 합친다.
   - 순서: 여러 창구에서 나온 말 → 검색이 많은 말 순. 가지마다 출처 표시는 하지 않는다(지도가 복잡해짐).
2. **가지에는 말로 된 표시 하나만** ('검색 흐름은 말로만, 숫자 없음' 결정 유지)
   - 우선순위: '요즘 오르는 중'(데이터랩 4주 변화 +20% 이상) > '많이 찾아요'(같은 지도 안 검색수 상위) > '○월에 많이 찾아요'(가장 많이 찾는 달). 해당 없으면 표시 없음
   - 여러 곳에서 나온 말은 점 하나로 '여러 곳에서 보여요'
3. **근거 패널(가지를 누르면)은 종류별 칸**
   - **검색**: 월 검색수(검색광고), 1년 흐름 작은 선(데이터랩), 구글 트렌드 흐름(있으면). 숫자는 여기서만. 두 곳이 다르게 움직이면 둘 다 보여 준다
   - **글**: 뉴스·블로그·카페 최신 몇 건 (제목, 날짜, 출처 이름 작게, 원문 링크)
   - **영상**: 유튜브 영상 몇 건 (제목, 채널, 올린 날)
   - **우리 데이터**: 작년 컨셉에 썼는지, 리뷰 언급, 명분 사전
   - 칸마다 맨 아래 작은 글씨로 출처 이름 + 받은 시각
4. **위쪽 거르기 칩**은 목업 21의 채널 칩(검색어·뉴스·SNS·블로그·트렌드 매체·우리 데이터)을 **검색 · 글 · 영상 · 우리 데이터** 네 개로 줄인다
5. **연결 상태는 한 줄로**: 지도 아래 '네이버 연결됨 · 유튜브 연결 안 됨 · 구글 트렌드 신청 중 [설정]'. 연결 안 된 종류의 칩은 흐리게, 누르면 무엇이 필요한지 안내
6. 검색어 묶음(§1)을 고르면 묶음의 검색어가 씨앗 여러 개가 되고, 가지는 위 1번 규칙으로 합친다
