# 탭 구좌를 02·03 어디서나 만들고 고치기 — 상세 구현 계획 (2026-11-15)

> 문제(사용자 피드백): 02 구좌 구성에서 탭 구좌를 추천받지 않으면 '고른 구성'에서도, 03 구좌 편집에서 구좌를 넣거나 바꿀 때도 탭 구좌를 찾을 수 없어 아예 쓸 수 없다.
> 기준 브랜치: `merge/2026-11-15` (05c7ebf). 이 문서는 계획만 담는다. 코드는 아직 바꾸지 않았다.

## 0. 지금 상태 (코드로 확인한 사실)

### 0-1. 탭 구좌는 '구좌 종류'가 아니라 구좌에 붙는 속성이다

| 층 | 모양 | 탭 지원 |
|---|---|---|
| 서버 저장 형식 `page.sections[]` | `tabs: [{tabId, label, zone_tag}]` (최대 12), `zone_kind`, `slots[].tabId` (없으면 첫 탭) — `amoread/api.py` `Tab`·`Section` | ✅ 있음 |
| 04 미리보기·내보내기 | 탭 알약, 탭별 카드 표, 표의 '구좌 · 탭' — `planner/static/v2/preview.js:264` | ✅ 있음 |
| 상품·할인 '놓인 곳' | `구좌 · 탭 이름` — `planner/static/v2/products.js` `placesOf` | ✅ 있음 |
| 02 구좌 구성 | 추천안에서 온 묶음만 [탭 하나로]/[따로 구좌로] 전환 | ⚠️ 만들기·고치기 없음 |
| 03 신규 편집기 (v1.12) | 탭 개념 없음 | ❌ 없음 |
| 예전 v2 편집기 `editor.js` | 탭 이름·추가·삭제·순서 (이미 탭인 구좌만) | 숨김 (`/v2/editor` → 신규 편집기) |

### 0-2. 탭 구좌가 생기는 길이 하나뿐이다
- 02 추천 **B안**만 탭을 만든다: PROMO_WORK 지난 상시 행사에서 같은 유형 진열 칸이 2개 이상 묶일 때 (`compose.js` `pastCand`).
- 서버 AI 추천 A·C안(`amoread/ai/compose.py`)은 탭을 만들지 않는다.
- 그래서 PROMO_WORK 데이터가 없거나 비슷한 지난 행사가 없으면 **탭 구좌가 한 번도 나오지 않는다**.

### 0-3. 02 '고른 구성'
- 탭 UI(`groupLine`, `compose.js:165`)는 추천 묶음 열쇠 `gk`가 있는 행에만 나온다.
- [+ 구좌 추가]는 탭 없는 `grid2`만 만든다.
- 일반 구좌를 탭으로 바꾸는 버튼이 없다. 탭 이름 고치기·추가·삭제도 없다. 줄에는 "고치기는 구좌 편집에서"라고 적혀 있지만 03에도 없다.
- 탭 id를 **순서 번호로** 이어 붙인다 (`toSections`: `o.tabs?.[j]`, `` `${r.id}t${j+1}` ``). 지금은 02에서 탭을 고칠 수 없어 문제가 없다. 하지만 탭 고치기를 넣으면 이름을 바꾸거나 순서를 바꾸거나 지울 때 **상품 칸(`slots[].tabId`)이 엉뚱한 탭에 붙는다**. 이번에 함께 고쳐야 한다.

### 0-4. 03 신규 편집기
- `fromLegacyPage` (`amoread_editor/editor/v1.12/app.js:1443`): 모든 탭의 상품 SEQ를 **한 목록으로 합치고 중복을 지운다**.
- `enToLegacy` (`planner/static/v2/editor-next-host.js`)
  - 새로 넣은 상품은 모두 **첫 탭**으로 간다 (`tabId: firstTab`).
  - 기존 칸은 SEQ 하나당 한 칸으로 찾는다 (`bySeq`).
  - → **같은 상품이 두 탭에 있으면 저장할 때 한 칸이 사라진다** (데이터 손실, 코드 읽기로 확인. 재현 테스트는 1단계에서).
- 편집기에서 새로 넣은 구좌는 탭이 없다. 구좌 유형을 바꿔도 이전 `tabs`가 그대로 남는다.
- 02가 바뀌었는지 알아보는 지문 `enLegacyMark`는 탭을 보지 않는다. 지금은 편집기가 탭을 건드리지 않아서 괜찮다. 하지만 03이 탭을 고치게 되면 02에서 바꾼 탭이 03에 반영되지 않는다.
- **이름 겹침 주의:** 편집기 안에 이미 `tabs(s)` 함수(`app.js:230`)와 전역 `tab` 변수가 있는데, 둘 다 **오른쪽 패널 탭**(문구·상품·레퍼런스…)이라는 뜻이다. 새 필드·함수는 `ftabs`(필터 탭)처럼 다른 이름을 쓴다.
- 구좌 추가 창은 변형을 고르는 방식이 이미 있다: `grid2@grid|list|card|carousel|masonry`, `notice@accordion` (`app.js:77`). 탭 상품도 같은 방식으로 넣을 수 있다.

## 3. 단계별 작업

### 구현하며 바꾼 것 (1·2단계, 2026-11-15)

- **`s.productIds` = 지금 보는 탭(`s.ftabCur`)의 상품**, 다른 탭 상품은 `s.ftabs[].productIds`에 보관한다. 처음 계획(`productIds` = 모든 탭 합침 + `syncFtabProducts`)은 상품을 고치는 기존 코드 4곳(체크·미리보기 삭제·자료 패널 넣기·순서)을 모두 고쳐야 했다. 이렇게 하면 탭을 바꿀 때만 목록을 맞바꾸고, 나머지 코드는 그대로 탭 단위로 동작한다.
- `ftabCur`는 저장본에 함께 저장된다(탭 바꾸기는 실행 취소 대상 아님). 앱 저장 변환(`enFtabs`)은 보던 탭의 목록을 `productIds`에서 읽는다.
- 도움 함수 이름: `ftOn·ftCur·ftStore·ftSwitch·ftSplit·ftAdd·ftRemove·ftMove·ftDrop·ftPills·ftIssues`, 오른쪽 칸 `ftabPanel` (`app.js` 앞부분).

### 1단계 — 03 저장에서 탭 지키기 (데이터 손실 먼저, 작음)

| 파일 | 바꿀 것 |
|---|---|
| `amoread_editor/editor/v1.12/app.js` `fromLegacyPage` | `x.tabs`가 있으면 `s.ftabs = [{id: tabId, label, zone: zone_tag, productIds}]`. 탭마다 `slots`에서 `(tabId \|\| 첫 탭)`으로 상품을 나눈다. `s.productIds`는 모든 탭을 합친 목록으로 계속 채운다 (기존 코드가 읽으므로 호환용) |
| `planner/static/v2/editor-next-host.js` `enToLegacy` | `s.ftabs`가 있으면 칸을 탭별로 만든다. 이전 칸은 `` `${tabId}\|${seq}` `` 열쇠로 찾고, 없으면 새 칸에 그 `tabId`를 붙인다. `tabs`는 `s.ftabs`에서 쓴다. 이전 `zone_tag`는 유지. `ftabs`가 없으면 지금처럼 (`p.tabs` 이어 받기) |

**확인:** PROMO_WORK B안으로 만든 탭 구좌, 같은 SEQ를 두 탭에 둔 기획안 → 03 열기 → 아무것도 안 고치고 저장 → 04에서 탭·상품이 그대로 (지금은 한 칸 사라지는 것을 먼저 재현).

### 4단계 (선택) — 추천에도 탭 구좌가 나오게

- `amoread/ai/compose.py`의 A안(필수 구좌 규칙)에 규칙형 탭 구좌를 더한다.
  - 예: 분류가 선물·시즌이면 '가격대별 추천' `grid2` + 탭 ['1만원대','2만원대','3만원 이상'], `kind:'가격대'`
  - 예: 고른 키워드가 3개 이상이면 '취향별 추천' + 키워드 탭
- `secs` 넷째 칸 `{kind, tabs}`는 `compose.js`가 이미 읽는다 (`toRows`). 서버만 바꾸면 된다.
- PROMO_WORK가 없는 PC에서도 추천에 탭 구좌가 보이게 하는 목적. 1~3단계로 직접 만들 수 있으니 필수는 아니다.
