# 추후 기능: 지난 기획안의 페이지 구성 가져오기

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-11-05 |
| 상태 | **추후 시도 (지금 범위 밖).** 데이터가 쌓이고 ③ 페이지 구성, ④ 구좌 편집이 안정된 뒤 검토 |
| 관련 | `plans/03_화면흐름_v0.2_기획안중심.md` 4장 ② `지난 행사 상품·할인 가져오기` |

## 1. 왜 필요한가
- `지난 행사 상품·할인 가져오기`는 상품과 할인만 옮긴다. 명분, 컨셉, 페이지 구성은 가져오지 않는다.
- 같은 명분(블프, 설, 홀리데이 등)은 해마다 페이지의 뼈대가 비슷할 수 있다. 예: 메인 비주얼 → 금액대별 선물 → 하루특가 → 혜택 안내
- 지난번 섹션 순서와 역할을 출발점으로 쓰면 ③을 처음부터 짜는 시간을 줄일 수 있다.

## 2. 왜 지금은 안 되는가 [사실]
- 페이지 구성은 **새 툴에서 만든 기획안에만 있다** (`planner/data/projects/*.json`의 `page.sections`).
- PROMO_WORK에는 페이지 구성이 없다. 행사 이름, 상품, Zone(카테고리명)만 있다. 기존 기획 도우미 기획안에도 페이지 정보는 없다.
- 따라서 새 툴로 기획안이 몇 건 쌓인 뒤에야 가져올 대상이 생긴다.

## 3. 가져오는 범위 (제안)

| 항목 | 기본 | 이유 |
|---|---|---|
| 섹션 순서, 섹션 이름 | 가져옴 | 뼈대 재사용이 목적 |
| 섹션 목표(전환, 유입 등), 역할 | 가져옴 | 구성 의도를 함께 옮김 |
| 레이아웃 | 가져옴 | 같은 배치를 다시 쓰기 쉬움 |
| 디자인 요청 | 선택 (기본 해제) | 지난 컨셉에 묶인 내용이 많을 수 있음 |
| 레퍼런스 연결 | 선택 (기본 해제) | 같은 레퍼런스를 다시 쓸지는 기획자가 정함 |
| 상품 자리 | 선택: `자리만` (기본) / `상품까지` / `가져오지 않음` | 상품은 ②에서 새로 정하는 경우가 많음. `상품까지`는 ②에 없는 상품을 '가격 미정'으로 표시 |
| 카피, CTA (④ 구현 후) | 가져오지 않음 (참고로만 표시) | 컨셉은 매번 달라야 한다는 원칙. 지난 카피는 옆에 회색으로 보여주는 정도 |
| 가격 | 가져오지 않음 | 가격은 ②의 할인 행이 정한다 |

화면에는 상품·할인 가져오기와 같은 방식으로 '가져와요'와 '가져오지 않아요'를 늘 보여준다.

## 4. 화면 위치와 흐름 (제안)
- 위치
  - ③ 페이지 구성의 시작 방법에 네 번째 카드 `지난 기획안 페이지 구성 가져오기`
  - ③ 도구 막대에도 같은 버튼 (섹션이 이미 있을 때)
- 흐름
  1. 후보 목록: 같은 명분(명분 사전 연결 `season_ref` 또는 명분 이름이 같은 것) → 같은 페이지 유형(이벤트, GNB) → 최근순
  2. 후보 미리보기: 섹션 썸네일 목록, 섹션 수, 당시 명분·컨셉(참고), 기간
  3. 가져오는 범위 선택 (3장)
  4. 적용
     - 지금 페이지가 비어 있으면 그대로 채움
     - 섹션이 있으면 `뒤에 추가` / `바꾸기` 중 선택. 기존에 고친 섹션은 바꾸기를 고른 경우에만 대체
  5. 가져온 섹션은 새 ID로 만든다. 원래 기획안은 바꾸지 않는다

## 5. 컨셉 차별화와의 관계
- 같은 구성을 반복하면 매번 다른 컨셉으로 가져가야 한다는 원칙과 부딪칠 수 있다.
- 대응
  - 가져온 뒤 '다음에 할 일'에 "지난 기획안과 섹션 순서가 같아요. 이번 컨셉에 맞게 바꿀 곳이 있는지 보세요"를 띄운다
  - 카피는 가져오지 않는다

## 6. 레퍼런스 라이브러리와의 차이
| 구분 | 지난 기획안 페이지 구성 | 레퍼런스 라이브러리 |
|---|---|---|
| 대상 | 우리가 새 툴에서 기획한 구조 (섹션 데이터) | 실제로 게시된 프로모션 페이지의 이미지와 구좌 |
| 쓰임 | 섹션 순서·목표·레이아웃을 출발점으로 복사 | 디자인 참고, 적용 가능한 경우 레이아웃 적용 |
| 연결 | 섹션의 `layoutSourceRefId`로 레퍼런스와 이어질 수 있음 | 기획안이 쌓이면 "이 레퍼런스를 쓴 지난 기획안" 역연결 가능 |

## 7. 시작 조건
- 새 툴로 만든 기획안 중 페이지 구성이 있는 것이 **같은 명분 기준 1건 이상, 전체 5건 이상** 쌓였을 때 검토를 시작한다 (임시 기준, 멘토님과 조정)
- ③ 페이지 구성의 섹션 데이터 구조가 ④ 구좌 편집 구현 후에도 바뀌지 않는다는 확인

## 8. 구현 메모
- API: `GET /api/am/projects?with_page=1&season=…&kind=…` 후보 목록 (요약만), 상세는 기존 `GET /api/am/projects/{id}` 재사용
- 복사는 화면에서 한다. 섹션과 슬롯에 새 ID를 붙이고, 3장의 선택에 따라 필드를 비운다
- 원래 기획안은 읽기만 한다
- 테스트: 가져오기 전후 원래 기획안 파일이 같은지, ID 중복이 없는지, 바꾸기를 고르지 않았을 때 기존 섹션이 그대로인지

## 9. 그때 확인할 질문
1. 같은 명분의 페이지 뼈대가 실제로 해마다 비슷한가 (멘토님 인터뷰 C3와 함께)
2. 상품 자리 기본값을 `자리만`으로 둘지
3. 지난 카피를 참고로 보여주는 것이 도움이 되는지, 오히려 반복을 부르는지
