# 트렌드 키워드 (amoread/trend)

브리프 화면(01)의 키워드 마인드맵에 **트렌드 가지**를 붙이는 서버 쪽 로직입니다. 수집·판정 로직은 `osulloc-concept-explorer`에서 옮겨 왔고, 화면은 우리 브리프 화면을 그대로 씁니다 (분류 칩 '트렌드'와 근거 패널의 트렌드 칸만 늘었습니다).

## 두 가지

| | 지금 뜨는 것 (급상승) | 공개 출처 탐색 |
|---|---|---|
| 무엇 | 뉴스·유튜브 쇼츠·MZ 뉴스레터에서 막 뜨는 **구체적인 이름** (떡픈런, 쫀득 모찌 밀크티…) + 차 인접 분야 | 명분(중심 키워드)으로 매거진·뉴스를 검색해 **여러 매체에 반복된 소비 현상** |
| 언제 | 매주 한 번 (매일 아침 자동 확인이 6.5일마다 부름) | 브리프를 열 때 (15~25초, 같은 검색 15분 캐시) |
| 판정 | 이름별 최근 14일 / 15~45일 전 / 46일~1년 전 기사 수로 단계를 고정 규칙으로 정함 (초기 급상승·확산 중·이미 대중화·꺾이는 중…) | 독립 매체 2곳·서로 다른 기사 4건 이상이면 트렌드 후보, 기획 기간이 미래면 선행 신호 후보, 전년과 비슷하면 시즌 반복 |
| AI | 후보 이름 고르기 + 오설록 아이디어 1개 (Claude Code, 공개 헤드라인과 확인된 상품 목록만 보냄) | 쓰지 않음 |
| 파일 | `planner/data/trend/rising/<날짜>.json`, `<날짜>_category.json` | 저장하지 않음 (서버 메모리 캐시) |

브리프에서는 여기에 **오늘의 영감**의 판매 기법(보관함에 저장한 카드 먼저, 그다음 오늘의 카드)도 2개까지 가지로 붙입니다 (`brief.js` trendBranches).

중심 키워드(명분)가 '연말정산 시즌'처럼 검색에 안 맞으면 브리프 근거 패널의 **[검색할 이름 고치기]**로 바꿀 수 있습니다. 끝이 시즌·기간·기획전 등이면 뺀 이름을 버튼으로 바로 제안합니다. 고친 이름은 기획안 `v2.root_kw`에 저장되고 캘린더의 명분은 그대로입니다. 바꾸면 가지·근거·트렌드를 새 이름으로 다시 찾습니다.

수치는 검색 결과 안의 서로 다른 기사 수입니다. 검색량·SNS 반응·판매량이 아니며 화면에도 그렇게 적습니다.

## AI가 지어내지 못하게

- 후보 목록에 없는 이름은 서버가 지웁니다 (`ai.validate`).
- 아이디어의 상품명은 `data/product_facts.txt`(공식몰 확인본) 안의 것만 남깁니다. 할인·증정·효능 표현, 목록 밖 구좌, 22자 넘는 문구는 '점검'으로 표시하고 문구를 몰래 고치지 않습니다.
- 공식몰 상품이 바뀌면 `data/product_facts.txt`를, 분야 검색어를 바꾸려면 `data/category_keywords.txt`를 고치면 다음 실행부터 반영됩니다 (코드 수정 없음).

## 실행

```
python -m amoread.trend.weekly             # 지금 뜨는 것: 기본 + 분야 (한쪽이 실패해도 다른 쪽은 함)
python -m amoread.trend.weekly --category  # 분야만
```

- AI 단계는 이 PC에 설치·로그인된 Claude Code CLI를 씁니다 (`claude` 로그인, API 키 불필요). 로그인이 안 돼 있으면 그 실행은 실패로 기록되고 이전 결과가 그대로 보입니다.
- `YOUTUBE_API_KEY`가 있으면 쇼츠 기간 비교까지 합니다 (하루 1회분 할당량). 없으면 그 단계만 건너뜁니다.
- 시험용: `AMOREAD_TREND_AI=mock` 이면 AI 없이 흐름만 확인합니다 (결과에 [가상 예시]).

API: `GET /api/am/trend/rising`, `POST /api/am/trend/discover {q, start, end}`, `GET /api/am/trend/status`, `POST /api/am/trend/run`.
