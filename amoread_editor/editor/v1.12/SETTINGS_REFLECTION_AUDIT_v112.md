# AMOREAD v1.12 — 구좌편집기 옵션→중앙 미리보기 반영 점검 (2026-11-14)

기준: `feat/composable-block-editor` / `integrated/v1.12/` (22개 구좌 유형 + 추가 가능한 구성 블록).

## 점검 기준

- **값 변경:** 우측 입력·토글·선택을 바꾸면 중앙 구좌에 해당 의미의 변화가 나타나야 한다.
- **구조 전환:** 배치 유형이 바뀌면 적용 불가능한 옵션은 숨기거나 조건을 설명하고, 기존 저장값은 삭제하지 않는다.
- **카드 독립성:** 상품 카드 한 장의 속성 숨김이 다른 상품 카드의 노출값을 바꾸면 안 된다.
- **삭제:** 캔버스 선택 → 삭제(툴바/키보드) → 실행 취소, 그리고 복원 가능한 속성은 우측 표시 설정에서 되돌릴 수 있어야 한다.
- **경계:** 실제 네트워크 API, 사내 승인·배송·추첨·쿠폰 발급은 동작 검증 대상이 아니라 별도 구현 필요 상태로 표시한다.

## 검토한 기존 연결

- **상품:** 이미지 종횡비, 이미지 위 모서리 라벨 위치, 할인율·정가·판매가, 가격 문구, 카드 요소 순서, 상품별 소구, 리스트/카드/캐러셀/메이슨리.
- **안내:** 제목·설명·추가 문구, 항목 순서, 조건·기간·중요도, 공지 아코디언, 수량·행 배열.
- **후기:** 상품별 연결, 배치 형식, 이미지·상품명·가격 표시, 순서와 열 수.
- **이벤트:** 퀴즈 질문/답/결과 시안, 공유 전후 상태, UGC 사진·댓글 조건, 출석 진행도, 뽑기 결과, 쿠폰 전후 상태.

이 범위는 코드를 대조한 기능 목록이다. **모든 조합의 자동 브라우저 통과를 의미하지 않는다.** 신규 테스트는 중점 결함 및 대표 조합에 우선 집중했다.

## 의도적으로 고객 미리보기에 바로 보이지 않는 설정

- 상품 ID/URL, 데이터 소스, 디자이너 요청, 참고 레퍼런스, 사내 데이터 식별자는 표시용 콘텐츠가 아니라 연결·인계 메타데이터.
- 실제 쿠폰 발급 수량, 추첨 확률, 로그인/인증, 법무 승인, API 기반 원가/할인가 등은 해당 Lab에 실제 운영 시스템이 연동되지 않아 **설정값만 저장하는 기획 모델**. 실 운영 기능이 동작하는 것처럼 시뮬레이션하지 않는다.
- 만료 시각의 실제 실시간 계산은 연결되지 않는다. 중앙 카운트다운은 예시라는 안내를 유지한다.
- 340px의 4열 상품 카드처럼 매우 좁은 구성이더라도 선택한 열 수를 우선 보여준다. 실디자인에서는 가독성 검토가 필요하다. 260px 미만의 극소형 임베디드 미리보기에서는 오버플로 방지를 위해 적게 표시할 수 있다.
