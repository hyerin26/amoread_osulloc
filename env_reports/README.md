# 환경 점검 결과 (env-check 브랜치)

회사 PC에서 외부 데이터 수집·자동 실행이 막히는 원인을 메일로 주고받지 않고 확인하기 위한 브랜치입니다.
회사 PC에서 점검을 돌리면 결과가 이 폴더에 올라오고, 개발 쪽에서는 브랜치를 받아 결과를 읽습니다.

## 회사 PC에서 (한 번에 1분쯤)

1. 프로그램 폴더(`osulloc`)에서 이 브랜치로 바꿉니다.
   ```powershell
   git fetch origin
   git switch env-check
   ```
2. `workspace\amoread_app\env_check.bat` 을 더블클릭합니다.
3. 끝나면 창에 `막힌 것 n개`와 목록이 나오고, 결과가 GitLab에 올라갑니다. 올리기가 실패하면 `env_reports\` 에 생긴 `.md` 파일을 그대로 전달해 주세요.

평소 작업으로 돌아갈 때는 `git switch main` 입니다.

## 무엇을 점검하나

| 묶음 | 내용 |
|---|---|
| 기본 | 파이썬 버전, 프로그램 환경(.venv), 필요한 패키지 |
| 네트워크 | 프록시를 쓰는지 (주소는 남기지 않음) |
| 접속 | 마켓·뉴스·유튜브·매거진·네이버 API·Claude·패키지 설치·GitLab 사이트마다 접속되는지, 막혔으면 어떻게 막혔는지 (인증서 확인 실패·시간 초과·회사 차단 페이지 등) |
| Chrome | 화면 수집용 Chrome이 켜지는지 (수정된 방식·기본 방식 둘 다), 29CM가 열리는지 |
| 예약 실행 | 작업 스케줄러에 예약을 만들 수 있는지 (시험용을 만들었다 바로 지움), 매일 아침 자동 확인이 등록돼 있는지와 마지막 결과 |
| PowerShell | 스크립트 실행 정책, 스크립트가 실제로 도는지, 프로그램 실행 제한(AppLocker) 유무 |
| AI | Claude Code 설치·로그인 여부 |
| 자동 확인 기록 | 마지막 자동 확인의 마켓별 성공·실패와 오류 문구 |

## 남기지 않는 것

PC 이름·사용자 이름·폴더 경로·IP 주소·프록시 주소는 지우거나 바꿔서 기록합니다. PC는 이름을 바꾼 6자리 코드로만 구분합니다.
그래도 회사 내부 정보가 보이면 올리지 말고 알려 주세요.

## 막힌 것이 나오면

- **접속이 막힘**: 결과 파일의 '막힌 것' 목록(주소와 용도)을 IT팀에 보내 열어 달라고 요청합니다.
- **인증서 확인 실패**: 회사 보안 장비가 인증서를 바꾸는 경우입니다. 설치 때 `pip-system-certs`를 넣었는지 확인하고, 안 되면 IT팀에 회사 인증서 사용 방법을 묻습니다.
- **예약 작업·PowerShell이 막힘**: 매일 아침 자동 실행 대신 화면의 [지금 한 번 확인]으로 직접 돌리거나, IT팀에 예약 작업 허용을 요청합니다.
